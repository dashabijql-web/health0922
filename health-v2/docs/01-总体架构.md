# 01 总体架构

## 一、系统全景

```text
                        ┌────────────────────────────────────┐
  智能手表 / 模拟器 ─TCP 9001─▶│  手表接入（Netty）                  │
                        │   解码 → 校验 → 放进 Redis 缓冲      │
                        └───────────────┬────────────────────┘
                                        │ 每 5 秒批量写库
                                        ▼
  人员定位厂家 ──FTP──▶  收件箱目录  ──▶ 定位文件接入（定时扫描 + 解析）
  (FileZilla Server)        │                      │
                            ▼                      ▼
                        备份目录             ┌───────────────┐
                                             │    Oracle     │◀── Flyway 迁移脚本
                                             └──────┬────────┘
                                                    │
                        ┌───────────────────────────┴──────────┐
                        │  业务后端（Spring Boot，端口 8081）    │
                        └───────────────┬──────────────────────┘
                                        │ REST（JSON）
                                        ▼
                        ┌──────────────────────────────────────┐
                        │  前端（Vue 3，端口 9529）              │
                        └───────────────┬──────────────────────┘
                                        │ WMS 地图图片
                                        ▼
                                    GeoServer（矿图）
```

几个名词：

- **Netty**：Java 里处理网络连接的库，手表用私有协议直连服务器所以需要它。
- **Redis 缓冲**：手表数据先放进 Redis 这个"暂存区"，再成批写进 Oracle，避免来一条写一次库。
- **Flyway**：管理建表脚本的工具，脚本按编号顺序执行。
- **WMS**：地图服务标准，GeoServer 按它把地图画成图片返回给前端。

## 二、两条数据线

| | 手表数据 | 定位数据 |
| --- | --- | --- |
| 来源 | 每块手表 | 矿上的人员定位系统 |
| 方式 | TCP 长连接，实时 | FTP 传 `.txt`，约每 5 分钟一份 |
| 数据量 | 大（每块表每分钟约 1 条） | 小（每次几十到几千条） |
| 缓冲 | Redis | 不需要，直接事务写库 |
| 详细设计 | `03` | `02` |

## 三、后端模块

一个 Maven 项目，按业务分包。

| 包 | 职责 |
| --- | --- |
| `auth` | 登录、账号 |
| `watch` | 手表接入：Netty、协议解码、会话、Redis 缓冲、批量落库 |
| `positioning` | 定位文件接入：扫描、解析、入库、备份、状态 |
| `health` | 体征查询：最新值、趋势、日汇总 |
| `alert` | 预警：阈值判断、设备报警、事件记录 |
| `dashboard` | 大屏聚合接口 |
| `map` | 地图配置、人员位置、基站摆放 |
| `archive` | 健康档案、个人档案 |
| `report` | 月度汇总、佩戴情况导出 |
| `common` | 统一返回格式、异常处理、操作日志组件 |

依赖单向：`dashboard / map / archive / report` 可调用 `health / positioning / alert`，反过来不行。`watch` 收到数据后调用 `alert` 判断预警（`03` 第四节），其余只写库；`watch` 和 `positioning` 互不调用。

## 四、技术选型

| 用途 | 选择 |
| --- | --- |
| 后端 | Java 21、Spring Boot 4、MyBatis（SQL 自己写，Oracle 的 `MERGE`、分区用起来直接） |

## 五、通用约定

**时间**：北京时间；数据库用 `TIMESTAMP`（不带时区），会话时区设为 `Asia/Shanghai`。手表数据没有时间字段，采集时间取服务器收到的时间。

**刷新**：前端每 30 秒轮询（定位数据最快 5 分钟才更新一次）。

**返回格式**：

```json
{ "code": 0, "message": "ok", "data": { } }
```

`code = 0` 成功。HTTP 状态码同时使用：未登录 401、无权限 403、参数错误 400、冲突 409。分页接口 `data` 为 `{ total, page, size, list }`，总数由后端算。

**配置**：放 `application.yml`，敏感信息用环境变量。各种时间阈值只在这张表里定义，其他文档引用这里。

| 配置项 | 环境变量 | 默认值 |
| --- | --- | --- |
| Oracle 连接 | `ORACLE_HOST` `ORACLE_PORT` `ORACLE_SERVICE` `ORACLE_USER` `ORACLE_PASSWORD` | 见 `.env.local`：没设环境变量时后端直接读这个文件（如在 IDEA 里运行），设了环境变量则以环境变量为准；上线时应用账号与建表账号分开（`04` 操作日志一节） |
| 集成测试用的 Oracle 用户 | `ORACLE_TEST_USER` `ORACLE_TEST_PASSWORD` | 见 `.env.local`，本机是 `HEALTH_V2_TEST`。后端测试会清空这个用户下的全部表再按迁移脚本重建，所以用户名必须以 `_TEST` 结尾，不能放业务数据；没配置时数据库测试跳过 |
| Redis | `REDIS_HOST` `REDIS_PORT` | `127.0.0.1` `6379` |
| 登录页是否显示默认账号提示 | `LOGIN_SHOW_DEFAULT_ACCOUNT` | `true`（上线前改为 `false`） |
| 手表 TCP 端口 | `WATCH_TCP_PORT` | `9001` |
| 是否监听手表 TCP 端口 | `WATCH_TCP_ENABLED` | `true`（后端测试里关掉） |
| 手表缓冲是否定时写库 | `WATCH_BUFFER_FLUSH_ENABLED` | `true`。只在演练时关掉（让数据先积在 Redis 里，如 `kill -9` 验收）；关掉时正常停止也不写库，数据留在 Redis |
| 手表缓冲的 Redis key 前缀 | `WATCH_BUFFER_KEY_PREFIX` | `hv2:watch:`，必须以 `hv2:` 开头；两个后端同时用一个 Redis 时（如压测）要分开 |
| 是否重算日汇总 `HEALTH_DAILY_SUMMARY` | `HEALTH_SUMMARY_ENABLED` | `true` |
| 定位收件箱 / 备份 / 失败目录 | `POSITIONING_INBOX_DIR` `POSITIONING_BACKUP_DIR` `POSITIONING_ERROR_DIR` | `health-v2/runtime/inbox` `backup` `error` |
| 本矿煤矿编码（只接收这个矿的文件） | `POSITIONING_MINE_CODE` | `620823009203` |
| 是否定时扫描收件箱 | `POSITIONING_SCAN_ENABLED` | `true` |
| 定位扫描间隔（秒） | `POSITIONING_SCAN_SECONDS` | `30` |
| 定位数据过期阈值（分钟） | `POSITIONING_STALE_MINUTES` | `15` |
| 文件头时间允许比现在晚多少（分钟） | `POSITIONING_FUTURE_TOLERANCE_MINUTES` | `5` |
| 手表最大连接数 | `WATCH_MAX_CONNECTIONS` | `2000` |
| 手表在线窗口（分钟） | `WATCH_ONLINE_WINDOW_MINUTES` | `20` |
| 单项体征"数据较旧"阈值（分钟） | `WATCH_VITAL_STALE_MINUTES` | `12` |
| 测量指令间隔（秒） | `WATCH_MONITORING_REFRESH_SECONDS` | `60` |
| 体征越界预警去重间隔（分钟） | `ALERT_DEDUP_MINUTES` | `30` |
| SOS、跌倒去重间隔（分钟） | `ALERT_DEVICE_DEDUP_MINUTES` | `2` |
| 告警"仍在发生"的时长（分钟） | `ALERT_ACTIVE_MINUTES` | `30` |

**安全**：

- 除 `/api/auth/login` 和 `/api/auth/login-hint` 外，所有接口要登录。
- 日志、错误信息里不输出密码、令牌、个人健康数据。
- 文件路径只接受配置目录里的文件，文件名里的目录部分一律丢弃。
- SQL 一律用参数绑定；表名、分区名只能来自代码里的固定白名单。
- 健康提示仅供参考，不是医学诊断；月报和档案页要写明这一句。
