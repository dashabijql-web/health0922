# 11 部署与运维

给矿上部署、日常运维用。上线服务器：**Windows Server，不能联网**，Oracle 企业版（`08` 阶段 7"已定"）。所有安装包和本项目的文件都在开发机上准备好，拷过去装。

本文里的路径以 `D:\hv2\` 为例，按服务器实际改。命令行里的 `curl` 是 Windows Server 2019 起自带的 `curl.exe`。

## 一、全景

```text
             办公网/调度室浏览器                手表所在网段                 定位厂家
                    │ 80                          │ 9001                        │ FTP 21 + 被动端口
  ┌─────────────────┼─────────────────────────────┼─────────────────────────────┼──────────────┐
  │ Windows Server  ▼                             ▼                             ▼              │
  │              nginx ──/api──▶ 后端 hv2-backend（127.0.0.1:8081，TCP 9001）◀── 收件箱 ◀── FileZilla Server
  │                │                    │      │                                               │
  │                └─/geoserver/hv2/wms─▶ GeoServer（127.0.0.1:8082）                            │
  │                                     │      └──▶ Redis（127.0.0.1:6380）                     │
  │                                     └──▶ Oracle（1521）                                     │
  └─────────────────────────────────────────────────────────────────────────────────────────────┘
```

| 组件 | 监听 | 谁能访问 |
| --- | --- | --- |
| nginx | `80` | 办公网、调度室 |
| 后端 HTTP | `127.0.0.1:8081` | 只有本机（nginx、运维） |
| 后端手表 TCP | `9001` | 只有手表所在网段（防火墙） |
| GeoServer | `127.0.0.1:8082` | 只有本机（nginx 只转 WMS） |
| Redis | `127.0.0.1:6380` | 只有本机 |
| Oracle | `1521` | 本机；数据库管理员远程维护时按需放行 |
| FileZilla Server | `21` 和被动端口（如 `50000-50100`） | 只有定位厂家的地址 |

目录：

| 目录 | 放什么 |
| --- | --- |
| `D:\hv2\backend\` | `hv2-backend.jar`、`hv2-backend.exe`（WinSW）、`hv2-backend.xml`（含数据库密码） |
| `D:\hv2\ops\` | `hv2-ops.jar`、数据库脚本 |

## 三、Oracle

**版本要求**（`10` 第 16 项核对的结论）：

- **19c 或更新**（19c、21c、23ai、26ai）。后端用的 JDBC 驱动是 Oracle 23 版的 `ojdbc17`，官方说明它只支持连接 19c、21c、23ai；Flyway 13 对 Oracle 的完整支持也是从 19c 开始。18c、12c 要换驱动，先告诉开发。
- 自增主键（`GENERATED ALWAYS AS IDENTITY`）要 12c 以上，19c 满足。
- `HEALTH_RECORD` 按月分区（`04`）：企业版有分区功能，但**分区是企业版的单独收费选件**（Partitioning Option），要和矿上确认买了没有。没买就不能用分区，`04` 写了替代做法（单表 + 夜间删旧数据），需要新写迁移脚本。

**两个账号**（`04` 第三节"操作日志"）：

| 账号 | 用途 | 权限 |
| --- | --- | --- |
| `HEALTH_V2` | 建表账号，表都属于它；只用来执行迁移、授权、删旧分区 | 建表、建视图、建触发器、建序列；表空间配额 |
| `HEALTH_V2_APP` | 应用账号，后端平时用它连库 | 只能登录；对操作日志只有 `SELECT`、`INSERT`，对其他表增删改查 |

应用账号没有建表、删表、清空表、停用触发器的权限，所以程序（哪怕被人利用）删不掉操作日志。数据库管理员仍能删，这是数据库本身的限制。

**第一次部署**（在服务器上，管理员命令行）：

1. 数据库管理员建 `HEALTH_V2`：

   ```sql
   CREATE USER HEALTH_V2 IDENTIFIED BY "<密码>" QUOTA UNLIMITED ON USERS;
   GRANT CREATE SESSION, CREATE TABLE, CREATE VIEW, CREATE TRIGGER, CREATE SEQUENCE TO HEALTH_V2;
   ```

   表空间按实际改。每年约 15 GB（`04` 体征流水表），留够空间。这五个权限够用：本机用只有这五个权限的临时用户执行过全部迁移和授权脚本。
2. 建表（迁移）。`hv2-ops.jar` 里带着迁移脚本，不用 Maven：

   ```bat
   set ORACLE_HOST=127.0.0.1
   set ORACLE_PORT=1521
   set ORACLE_SERVICE=ORCLPDB1
   set ORACLE_USER=HEALTH_V2
   java -jar D:\hv2\ops\hv2-ops.jar migrate
   ```

   不设 `ORACLE_PASSWORD` 时运行中提示输入，输入不显示。`info` 看执行到第几号，`validate` 校验库里执行过的脚本和 jar 里的一样。工具不允许清空数据库。
3. 数据库管理员建应用账号（运行中输入它的密码，密码里不要有双引号；可以重复执行，账号已存在时改密码、解锁）：

   ```bat
   sqlplus system@//127.0.0.1:1521/ORCLPDB1 @D:\hv2\ops\oracle\create-app-user.sql HEALTH_V2_APP
   ```

4. 用 `HEALTH_V2` 给应用账号授权：

   ```bat
   sqlplus HEALTH_V2@//127.0.0.1:1521/ORCLPDB1 @D:\hv2\ops\oracle\grant-app.sql HEALTH_V2_APP
   ```

   结尾会列出操作日志表的权限，应当只有 `INSERT`、`SELECT`。

**以后升级**：先执行第 2 步（新的迁移脚本），**再执行第 4 步**（新表才有权限），最后换后端 JAR、重启后端。

**本机实测**（2026-10-02，Oracle 26ai Free，测试用户 `HEALTH_V2_TEST` 当建表账号、`HEALTH_V2_TEST_APP` 当应用账号）：

- 空库上 `hv2-ops migrate` 执行 5 个脚本；再执行一次"执行了 0 个"；`validate` 通过；开发用的 `mvn flyway:validate` 对同一个库也通过，两个工具可以混用。
- `create-app-user.sql` 在终端里执行两次（第一次建、第二次改密码），输入的密码不显示、不出现在输出里；账号只有 `CREATE SESSION`。`grant-app.sql` 执行两次结果一样（22 张表、1 个视图）；把建表账号自己当应用账号传进去被拒绝。
- 用应用账号：操作日志 `INSERT`、`SELECT` 成功；`UPDATE`、`DELETE` 报 `ORA-41900`（缺少权限），`TRUNCATE`、停用触发器、建表、删表、删分区都报 `ORA-01031`；其他表可以改。往一个还没有分区的月份写数据，Oracle 自动建了分区（1 个变 2 个），应用账号不需要建表权限。
- 后端用应用账号跑了全部功能（手表入库、定位入库、基站摆放、改年龄、月报、导出、冒烟脚本 137 项），见 `08` 阶段 7 的实测结果。

**删旧分区**（体征流水保留 12 个月，`04`）：程序不做，应用账号也没有这个权限。每月由数据库管理员用 `HEALTH_V2` 执行一次：

```sql
-- 看有哪些分区和它们的上界
SELECT PARTITION_NAME, HIGH_VALUE FROM USER_TAB_PARTITIONS WHERE TABLE_NAME = 'HEALTH_RECORD' ORDER BY PARTITION_POSITION;
-- 删掉 13 个月前那个月（例：删 2026 年 9 月的数据），本地索引跟着一起删
ALTER TABLE HEALTH_RECORD DROP PARTITION FOR (TIMESTAMP '2026-09-15 00:00:00') UPDATE GLOBAL INDEXES;
```

月报用的是日汇总表，删明细不影响历史报告。

## 四、Redis

后端用 Redis 做手表数据的暂存区和登录失败计数。要求：只监听本机、开启持久化（AOF），Redis 重启后没写库的手表数据不丢（`03` 第五节）。端口沿用 `6380`。

**Windows 上装哪个待定**（`00` 待确认第 23 项）：Redis 官方不出 Windows 版。可选：

| 做法 | 说明 |
| --- | --- |
| Memurai | 兼容 Redis 的 Windows 原生服务；生产使用要买授权 |
| 社区编译的 Redis for Windows | 免费，非官方 |
| WSL2 里装官方 Redis | 要 Windows Server 2022 以上且开启 WSL2 |

不管哪种，配置都是：

```text
bind 127.0.0.1
port 6380
appendonly yes
```

Redis 停了后端照常接收、写库（降级为内存队列，`03` 第五节），但登录失败锁定失效，要尽快恢复。

## 五、后端

1. `hv2-backend.jar`、WinSW（改名 `hv2-backend.exe`）、`hv2-backend.xml` 放进 `D:\hv2\backend\`。
2. 编辑 `hv2-backend.xml`：Java 路径、Oracle 连接和应用账号密码、目录。模板里每一处都标了"按实际改"。**`LOGIN_SHOW_DEFAULT_ACCOUNT` 必须是 `false`。**
3. 收紧这个文件的权限（里面有数据库密码），只留 Administrators 和 SYSTEM：

   ```bat
   icacls D:\hv2\backend\hv2-backend.xml /inheritance:r /grant:r Administrators:F SYSTEM:F
   ```

4. 安装并启动服务：

   ```bat
   cd /d D:\hv2\backend
   hv2-backend.exe install
   hv2-backend.exe start
   curl http://127.0.0.1:8081/actuator/health
   ```

   返回 `{"status":"UP"...}` 即可。

配置项的含义见 `01` 配置表。模板里的几项上线专用：

| 配置 | 值 | 为什么 |
| --- | --- | --- |
| `SERVER_ADDRESS` | `127.0.0.1` | HTTP 只给本机的 nginx 用；`/actuator` 不用登录，不能让外面直接访问 |
| `ORACLE_USER` / `ORACLE_SCHEMA` | `HEALTH_V2_APP` / `HEALTH_V2` | 用应用账号登录；表在 `HEALTH_V2` 下，连接时切过去（`common/config/OracleSessionConfig`） |
| `LOGGING_FILE_NAME` 等 | `D:\hv2\logs\backend.log` | 后端自己写日志文件，每天、每 10 MB 滚动一个，保留 30 天、最多 2 GB |

**停止**：`hv2-backend.exe stop`。WinSW 先让后端正常退出：先关 9001，再把缓冲里的数据写完（最多约 30 秒），模板里给了 60 秒。正常停止的日志最后有"停止前缓冲已全部写库"。**不要在任务管理器里直接结束 java.exe**，那样缓冲里的数据要等下次启动才写库（不会丢，在 Redis 里）。

**启动时的检查**：后端启动时如果发现 `admin` 还是默认密码，或者密码已改但登录页提示没关，会在日志里记一条 `WARN`（`auth/DefaultPasswordCheck`）。上线后日志里不应有这条。

## 六、前端和 nginx

1. 安装包里 `frontend\` 的内容拷到 `D:\hv2\frontend\`。
2. nginx 解压到如 `D:\nginx\`；`hv2.conf` 放进 `D:\nginx\conf\`，在 `conf\nginx.conf` 的 `http { }` 里加一行 `include hv2.conf;`，并删掉（或注释）`nginx.conf` 自带的那个 `server { listen 80; ... }`。按 `hv2.conf` 里标"按实际改"的三处改好路径和端口。
3. 检查配置、启动：`nginx -t`，然后 `start nginx`。nginx 装成服务同样用 WinSW。

`hv2.conf` 做的事：

- `/` 是前端静态文件。前端用 hash 路由（`/#/...`），找不到的文件就是 404，不回退到首页。
- `/api/` 转给后端 `127.0.0.1:8081`。
- 只有 `/geoserver/hv2/wms` 这一个地址转给 GeoServer，而且只允许 `GET`。底图不用登录就能取（`06` 第二节，`08` 阶段 7 已定：矿上是内网，保持现状）。GeoServer 的管理页面、REST 接口、其他工作区一律 404。
- `/actuator/` 一律 404，运行指标只在服务器本机看。
- 首页不缓存，`/assets/` 下带摘要的文件缓存 30 天；JS、CSS 压缩传输；加了几个安全响应头。

**本机实测**（2026-10-02，nginx 1.30.5 官方 Docker 镜像，配置只改了根目录和转发地址）：首页、静态文件、`/api/auth/login-hint` 200；不带令牌的业务接口 401；WMS 取图 200，`POST` 403；`/geoserver/web/`、`/geoserver/rest/...`、`/geoserver/wms`、`/geoserver/hv2/wms/../../rest/...`、`/actuator/health`、`/actuator/metrics` 都是 404；经 nginx 跑冒烟脚本 137 项全部通过（地图模式 2 次 WMS 请求、都用 1.1.1）。

## 七、GeoServer

1. 解压 GeoServer 2.28.5 到如 `D:\geoserver\`，用 JDK 21 运行。
2. **只监听本机 8082**：改 `D:\geoserver\start.ini`：

   ```ini
   jetty.http.host=127.0.0.1
   jetty.http.port=8082
   ```

3. **装中文字体**：巷道名称的样式用"文泉驿微米黑"（`tools/map-prep/styles/roadway_label.sld`），Windows 自带的没有。在安装包 `map\wqy-microhei.ttc` 上右键"为所有用户安装"，然后重启 GeoServer。
   不装时 Java 会换成系统里别的中文字体，字照样能显示，但样子和开发时不一样（本机试过：样式里只写一个不存在的字体，GeoServer 用默认字体画出来的中文和指定文泉驿时一模一样，所以光看"有没有方块"判断不出字体装没装好，要看字形）。样式里写多个备选字体没用：GeoServer 保存样式时只留第一个（本机试过）。
4. **改 GeoServer 管理员密码**：GeoServer 自带的管理员是公开的 `admin` / `geoserver`。第一次启动后，在本机浏览器打开 `http://127.0.0.1:8082/geoserver/web/`，登录后在"安全 → 用户、组、角色"里改掉。nginx 不转发管理页面，外面本来就进不来，但仍要改。
5. **发布底图**：`mine-map.gpkg` 拷到 `D:\hv2\map\`，然后

   ```bat
   java -jar D:\hv2\ops\hv2-ops.jar publish-map --gpkg D:\hv2\map\mine-map.gpkg --geoserver http://127.0.0.1:8082/geoserver
   ```

   运行中输入 GeoServer 管理员密码。做的事和开发用的 `tools/map-prep/publish.sh` 一样，可以反复运行（先删工作区 `hv2` 再重建）。本机对开发用的 GeoServer 运行过：发布前后同一范围的底图图片逐字节相同。
6. 检查：`curl -o test.png "http://127.0.0.1/geoserver/hv2/wms?SERVICE=WMS&VERSION=1.1.1&REQUEST=GetMap&LAYERS=hv2:roadway_line,hv2:roadway_label&STYLES=&SRS=EPSG:4527&BBOX=39480087.9,3851797.4,39489391.2,3854743.4&WIDTH=1400&HEIGHT=444&FORMAT=image/png"`，打开图片能看到巷道和中文名称。

## 八、FileZilla Server（接收定位文件）

1. 安装 FileZilla Server，管理界面只在本机打开。
2. 给厂家建一个用户，**挂载点**（虚拟路径 `/`）指向 `D:\hv2\runtime\inbox\jxry\620823009203\`。厂家只需要上传：给"读取、写入"，不给删除、改名、建目录。
3. 被动模式端口设一个范围，如 `50000-50100`，防火墙只对厂家地址开放 `21` 和这个范围（第十节）。
4. 能用 FTPS（加密）就用：要先问厂家支不支持（`00` 待确认第 24 项）。

**和后端的配合**：后端每 30 秒扫描收件箱，只处理以 `||` 结尾的完整文件；还在上传的文件本轮跳过，10 分钟还不完整才移到失败目录（`02` 第二节）。Windows 上正在写的文件可能被锁着读不了、挪不动，这时后端记一条日志、留在收件箱，下一轮再试，不会当成失败。FileZilla Server 是不是先写临时文件名再改名，要用真实上传核对（`10` 第 15 项，第十三节 B2）。

## 九、目录权限

后端和 FileZilla Server 各用一个**专用的 Windows 账号**运行服务，不用 Administrator（WinSW 的 `<serviceaccount>`、FileZilla Server 的服务属性里设）。

| 目录 | 后端账号 | FileZilla 账号 | 其他 |
| --- | --- | --- | --- |
| `D:\hv2\backend\` | 读 | — | 管理员完全控制；`hv2-backend.xml` 只给 Administrators、SYSTEM |
| `D:\hv2\runtime\inbox\` | 修改（读、写、删） | 写入 | |
| `D:\hv2\runtime\backup\` `error\` | 修改 | — | |
| `D:\hv2\logs\` | 修改 | — | |
| `D:\hv2\frontend\` | — | — | nginx 账号读 |
| `D:\hv2\map\` | — | — | GeoServer 账号读 |

后端只读写配置的这几个目录，文件名里的目录部分一律丢弃，符号链接不跟着读（`01` 第五节"安全"、`02` 第二节）。

**本机实测**（A8）：把备份目录改成不可写，生成一份 `RYSS` 和 `JZSS`：两个文件都留在收件箱，日志各一条"复制到备份目录失败，留在收件箱下一轮重试"（`AccessDeniedException`），没有写库；改回可写后，下一轮（30 秒内）两个文件都 `DONE`、收件箱清空。

## 十、防火墙

Windows Defender 防火墙，入站默认拒绝，只开下面几条（管理员 PowerShell，地址按实际改）：

```powershell
# 网页：办公网、调度室
New-NetFirewallRule -DisplayName "hv2 web"   -Direction Inbound -Protocol TCP -LocalPort 80   -RemoteAddress 10.0.10.0/24 -Action Allow
# 手表：只放行手表所在网段（协议没有认证，谁能连上 9001 谁就能冒充任意手表，docs/03 第二节）
New-NetFirewallRule -DisplayName "hv2 watch" -Direction Inbound -Protocol TCP -LocalPort 9001 -RemoteAddress 10.0.20.0/24 -Action Allow
# 定位厂家的 FTP：控制端口和被动端口范围，只放厂家的地址
New-NetFirewallRule -DisplayName "hv2 ftp"   -Direction Inbound -Protocol TCP -LocalPort 21,50000-50100 -RemoteAddress 10.0.30.5 -Action Allow
```

`8081`（后端 HTTP）、`8082`（GeoServer）、`6380`（Redis）本来就只监听本机，不开。`1521`（Oracle）只在数据库管理员需要远程维护时对他的地址开放。

**本机能证明的**：测试环境里后端 HTTP 只监听 `127.0.0.1:8083`，手表端口 `*:9011` 监听所有网卡（手表要从网络连进来，所以必须靠防火墙限制来源）。规则本身是否生效，到上线服务器上用另一台机器验证（第十三节 B5）。

### 定位数据过期

**现象**：大屏顶部"定位数据已过期"，井下人数不变。最新一份 `RYSS` 的上传时间距现在超过 15 分钟（`POSITIONING_STALE_MINUTES`）。

**排查**：

1. `/api/positioning/status`：`stale`、`lastDataTime`（最后数据时间）、每种文件最后一份的状态和错误原因、`failedLast24h`（24 小时内失败几份）。
2. 收件箱里有没有积压的文件：
   - **有，而且越积越多**：后端没在处理。看后端是否在运行、日志里有没有"数据库暂时不可用"（数据库连不上时文件留着等下一轮）、"复制到备份目录失败"（见下一节）。
   - **没有**：文件没到。看 FileZilla Server 的日志有没有厂家登录和上传；问厂家是否在发。
3. 失败目录里有没有新文件：有就看 `POS_INGEST_FILE.ERROR_MSG`。常见原因：文件头时间比服务器晚 5 分钟以上（**服务器或厂家的时钟不准**，两边都对时）、超过 20% 的记录出错（厂家格式变了）、不是本矿的煤矿编码。
4. 修好后不用重启，下一份文件到了 30 秒内就恢复。失败目录里的文件修好后可以放回收件箱重新处理。

**本机演练**（过期阈值临时设成 2 分钟）：停掉定位生成器后状态变成 `stale=true`；收件箱 0 个文件（说明是"没发"）；失败目录、处理记录里看到前面故意造的两份失败文件和原因；生成一份新的 `RYSS`，30 秒内 `stale=false`。

### 手表全掉线

**现象**：大屏"已上线"人数很少或为 0。

**先看连接数**：`health.watch.connections` 是**当前**连着的手表数，掉线后几秒内就变；`health.watch.online.count`（在线数）要等 20 分钟在线窗口过了才降。所以连接数是 0 而在线数还高，说明刚刚整体断开。

**排查**：

1. 后端在不在跑、9001 还在不在监听：`netstat -ano | findstr :9001`。
2. 日志里有没有"手表 TCP 服务已停止"、连接数满（`health.watch.dropped` 里 `connection_limit` 增加）。
3. 防火墙、网络：手表所在网段到服务器 9001 通不通（在那个网段的机器上 `Test-NetConnection <服务器> -Port 9001`）。
4. 数据库里最后一次收到数据的时间：`SELECT MAX(LAST_SEEN_AT) FROM DEVICE WHERE STATUS = 1;`，对照是什么时候断的。
5. 只有一部分表掉线：看是不是没电（设备事件里的低电）、没登记或没绑定（`health.watch.dropped` 里的 `unregistered`、`unbound`）。

**本机演练**（在线窗口临时设成 2 分钟）：停掉手表模拟器，3 秒后连接数 202 → 0，在线数仍是 200；9001 照常监听；`DEVICE` 最后收到数据 11:15:52；约 2.5 分钟后在线数变 0。重新启动模拟器，全部重连。

### 备份目录写满

**现象**：定位数据过期；收件箱里文件越积越多；日志每 30 秒出现"复制到备份目录失败，留在收件箱下一轮重试"。

**本机演练**：见第九节"本机实测"。

### 基站位置偏差

**现象**：地图上某人的位置明显不对，或者基站被拖到了别处。

**排查**：

## 十四、稳定性观察与压测

`hv2-ops soak` 每隔一段时间（默认 60 秒）从后端的 `/actuator/metrics` 取一次指标，写进 CSV，结束时打印摘要；`soak-summary <csv>` 对已有的 CSV 重新出摘要。它只读本机的 Actuator，不用登录，所以在后端所在的机器上运行。

| CSV 列 | 含义 |
| --- | --- |
| `up` | 后端有没有响应 |
| `connections` `online` | 连接数、在线数 |
| `buffer` | 缓冲积压条数 |
| `flushes` `flushAvgMs` `flushMaxMs` | 这一分钟写了几批、平均每批多少毫秒、最近的最慢一批 |
| `packets` `dropped` `dead` `memoryDropped` | 这一分钟收包、丢弃、进死信、降级队列丢弃的条数 |
| `summaryRuns` `summaryMaxMs` | 日汇总重算次数、最近的最慢一次 |
| `posDone` `posFailed` | 这一分钟入库、失败的定位文件份数 |
| `heapMb` `threads` `cpu` `dbActive` | Java 堆内存、线程数、CPU、正在用的数据库连接 |

**怎么判断稳定**：缓冲积压不持续增长；每批写库耗时、堆内存、线程数不随时间上涨；没有死信和降级丢弃；定位文件一直在入库、没有失败。

**本机结果**：见 `08` 阶段 7 的验收记录。
