# 08 开发计划

**先做数据入口，再做页面**：页面的数字都来自数据，没有真实流动的数据，页面无法验证。

## 一、总览

| 阶段 | 名称 | 规模 | 依赖 |
| --- | --- | --- | --- |
| 0 | 工程脚手架 | 中 | — |
| 1 | 定位文件接入 | 中 | 0 |
| 2 | 手表数据链路 | 大 | 0 |
| 3 | 入口页 + 动态数据页（展示模式）+ 佩戴情况导出 | 大 | 1、2 |
| 4 | 地图模式 + 基站摆放 | 大 | 1、3，需要你挑选 CAD 图层 |
| 5 | 健康档案 + 个人档案 | 中 | 2、3 |
| 6 | 月度汇总（翻书） | 中 | 2、5 |
| 7 | 联调与上线准备 | 中 | 全部 |
| 8 | 后台管理 | 大 | 7 |

规模只表示相对工作量。阶段 1 和 2 互不依赖，顺序可调换。

## 二、各阶段

### 阶段 0：工程脚手架

- 后端：Spring Boot 4 + Java 21；Oracle 连接；Redis 连接（登录锁定要用）；Flyway；统一返回格式与异常处理；Sa-Token 登录；操作日志组件；Actuator。迁移 `V001`、`V002`。
- 前端：Vue 3 + Vite + TypeScript + Pinia + Vue Router；`tokens.css`；1920×1080 等比缩放容器；`Panel`、`EmptyState`、`NoticeBanner`；axios 封装；从老项目复制的登录页；logo。
- 开发辅助：`tools/dev/` 下的启动、停止、状态检查脚本；前端冒烟脚本（Playwright，逐页打开，检查控制台报错和 HTTP 错误），之后每个阶段往里加页面。集成测试用 Oracle 里一个专用测试用户，不用业务用户。

**验收**

- [ ] `mvn flyway:migrate` 成功。
- [ ] 对 `SYS_OPERATION_LOG` 执行 `UPDATE`/`DELETE` 被触发器拒绝。
- [ ] `/actuator/health` 顶层 `status` 为 `UP`。
- [ ] 登录页显示"默认账号 admin，密码 admin"，用它能登录；`LOGIN_SHOW_DEFAULT_ACCOUNT=false` 时提示消失。
- [ ] 登录拿到令牌；不带令牌访问业务接口返回 401；连续 5 次密码错误后账号被锁，10 分钟后自动解除。
- [ ] 前端首页在 1920×1080 和 1366×768 下完整显示，无滚动条。

### 阶段 1：定位文件接入

- `V003`；扫描器、文件名校验、完整性判断、去重、直接删除的类型、备份与失败目录；五类文件的解析与入库；按文件头时间判断新旧；`GET /api/positioning/status`。
- 定位文件生成器 `tools/positioning-sim/`，脱敏假数据的单元测试。

**验收**

- [ ] 生成器造的文件放进收件箱，30 秒内入库，原文件在备份目录。
- [ ] `02` 第六节的必测用例全部通过。
- [ ] 用真实样例（只在本机）跑一遍，数量对得上：
  - `RYXX` 1517 条记录，其中一个卡编码出现两次，`POS_PERSON` 里来自 `RYXX` 的是 1516 人，并有一条"重复卡编码"警告；
  - `RYSS` 85 人，其中 14 人不在 `RYXX` 里，补录后 `POS_PERSON` 共 1530 人；
  - `RYQY` 31 个区域；
  - `RYJZ` 130 个基站、`JZSS` 131 个基站，合并后 `POS_STATION` 共 133 个（`JZSS` 多出 3 个没有名称的）；
  - `V_POS_IN_WELL` 返回 82 人。
- [ ] 停止扫描 15 分钟后，`/api/positioning/status` 显示数据过期。

### 阶段 2：手表数据链路

- `V004`、`V005`；Netty（9001）：切包、解码、会话、登录与心跳回复；有效性判断；Redis 缓冲、批量写库、重试与死信、Redis 不可用时降级；最新值、日汇总（`HEALTH_DAILY_SUMMARY` 汇总任务：5 分钟刷新今天，0:10 定稿昨天）、步数、累计计数；预警引擎（按岗位类别取阈值）；服务器下发测量指令。
- 手表模拟器 `tools/watch-simulator/`，设备与假人绑定的初始化脚本（与定位生成器同一批假人，`sim.py bind`）；查数脚本 `tools/dev/sql.sh`。
- 实测结果（吞吐、Redis 停机、`kill -9`、1 小时稳定运行、1000 块表时日汇总耗时）记在 `03` 第九节。

**验收**

- [ ] 200 块模拟手表，`health.watch.online.count` 约 200；一段时间后 `HEALTH_RECORD` 有数据，`HEALTH_LATEST` 每人每指标一行。
- [ ] 模拟没戴（发 `0`）：不入库，`health.watch.dropped` 增加。
- [ ] 两个人分属不同岗位类别，心率都是 125：只有阈值低于 125 的那一类产生告警，事件里记着 `RULE_GROUP`；工种未归类的人按 `DEFAULT` 判断。
- [ ] 模拟高心率产生一条 `ALERT_EVENT`，30 分钟内再次高心率只更新次数；模拟 SOS 产生 `CATEGORY=SOS` 的事件。
- [ ] 步数：计数器回绕、手表重启、跨过 0 点、首次上线、换绑，当天步数都不减少、无巨大跳变。
- [ ] 写库中途强制杀掉后端进程（`kill -9`）再启动：数据不丢，`HEALTH_RECORD` 没有重复行，累计条数和步数没有多算。
- [ ] 一批数据里混一条写不进库的坏数据：只有这一条进 `dead`，其余正常入库。
- [ ] 未绑定的手表发 SOS：`ALERT_EVENT` 有记录（卡编码为空），大屏 SOS 计数加 1。
- [ ] 在线的手表改绑定：1 分钟内新数据记到新的人名下，不用重连。
- [ ] 收到 `APXL` 等指令确认包时，服务器不回复。
- [ ] 停掉 Redis：接入不中断，数据仍能写库，Redis 恢复后正常。
- [ ] 正常停止后端：缓冲区数据不丢。
- [ ] 稳定运行 1 小时：`health.buffer.size` 不持续增长，每批写库耗时稳定。

### 阶段 3：入口页 + 动态数据页 + 佩戴情况导出

- 接口：`portal/summary`、`dashboard/*`、`export/wear`（`HEALTH_DAILY_SUMMARY` 汇总任务已在阶段 2 做好）。
- 前端：入口页、动态数据页（展示模式）、公共组件、数字滚动、上线曲线、人员表、排行、六类告警。人员表"点击某一行跳到地图模式并定位"要等阶段 4 地图做好才能验收，本阶段先只做到切换模式。
- 首页中央动画（`tools/hero-render/`）；佩戴情况确认弹窗与 Excel 下载。

**验收**

- [ ] 页面上每个数字都能用一条 SQL 复算出一致的结果（SQL 记在测试里）。
- [ ] "已上线无告警 + 已上线告警 = 已上线"，"未上线 = 应上线 − 已上线"。
- [ ] 模拟一个人心率偏高后恢复正常：30 分钟后他从"已上线告警"回到"已上线无告警"，心率告警格子的今天人数不减少。
- [ ] 模拟低电、脱落：标题栏"设备事件"数量增加，点开列表能看到；未绑定手表的事件显示 IMEI。
- [ ] 定位文件停 15 分钟：出现"定位数据已过期"横幅；后端停掉：页面保留上次数据并显示"刷新失败"。
- [ ] Excel：工作表名"数据上报记录"，列与 `05` 一致，"上报数据"与库里记录一致。
- [ ] 前端冒烟脚本通过（无控制台报错、无 HTTP 错误）。

### 阶段 4：地图模式 + 基站摆放

**需要你参与两次**：挑选 CAD 图层；用真实数据验收底图位置。

- 数据准备（`tools/map-prep/`）：DWG → DXF → 图层清单和预览 → 你挑选 → GeoPackage → GeoServer 发布线和文字图层，配样式和中文字体。
- 地图接口、OpenLayers 前端、体征卡、重点监护/今日关注过滤、搜索；摆放模式（列表、放置、拖动、保存、改名、删除、自动跳下一个、操作记录抽屉）；操作日志。

**验收**：`06` 第七节全部通过，另加：

- [ ] 用摆放功能把 133 个基站（按样例数据）完整摆一遍，操作流畅。
- [ ] 人所在基站已摆放/未摆放，两种情况显示都正确。

### 阶段 5：健康档案 + 个人档案

- 接口：`archive/*`、年龄录入、名单管理。前端：卡片列表（4×3 翻页）、个人档案页、加入重点监护/今日关注；3D 人体封装为 `BodyModel3D`（模型文件从老项目复制）。

**验收**

- [ ] 筛选结果正确，总数与数据库一致，翻页正确。
- [ ] 年龄未录入显示"未录入"，录入后立即显示且操作日志有记录。
- [ ] 没有手表数据的人：个人档案不报错，图表显示"暂无数据"。
- [ ] 反复进出个人档案，3D 人体正确释放，不卡、不泄漏内存。

### 阶段 6：月度汇总

- 聚合接口（只读汇总表）、月份列表、缓存；历史数据回填工具（生成一个月的假数据，用来测试报告）。手表数据的采集时间就是服务器收到的时间，没法通过 TCP 补上个月的数据，所以回填工具直接写 `HEALTH_DAILY_SUMMARY`、`STEP_DAILY`、`ALERT_EVENT`；定位数据仍按规则生成带过去时间的文件放进收件箱。回填工具只用于测试库；`MonthlyReportBook`、13 页、空数据插画、月份选择、键盘和页角交互。

**验收**

- [ ] 翻页流畅，页角卷起、键盘翻页、`Esc` 关闭都正常。
- [ ] 每页数字都能用 SQL 复算一致。
- [ ] 没有数据的月份/页面显示"暂无数据"。
- [ ] 样本不足的人不参与稳定性评估，页面注明人数；每页有免责声明。
- [ ] 两个岗位类别配不同的分界线，同样正常率的两个人得到不同的评估结果；没配的类别用默认值。

### 阶段 7：联调与上线准备

- 定位文件联调：用 FileZilla Server 真实传文件，验证完整性判断；核对厂家真实 `RYSS`。
- 手表联调：真实手表验证 `BP33`/`BP86`/`BP87`/`BPXL` 等指令的效果和未佩戴时的数据形态；`docs/10` 里标在阶段 7 的待核对项逐条核对。
- 部署文档（后端 JAR、前端静态文件 + Nginx、Oracle、Redis、GeoServer、FileZilla Server）；24 小时稳定性观察；安全检查（修改 `admin` 的默认密码，`LOGIN_SHOW_DEFAULT_ACCOUNT` 改为 `false`；接口鉴权覆盖、日志无敏感信息、目录权限；后端改用单独的应用数据库账号，操作日志表只有 `INSERT`/`SELECT` 权限，见 `04`；防火墙只允许手表所在网段连接 9001）；运维手册（定位数据过期、手表全掉线、备份目录写满、基站位置偏差的排查）。

### 阶段 8：后台管理

范围到时再和你确认，预计包括：账号管理、人员管理（录入年龄）、手表管理（绑定/解绑、Excel 批量导入）、岗位类别管理、工种归类（含"未归类工种"清单）、各岗位类别的预警阈值配置、名单规则配置、操作日志查询；月报文字的 AI 生成（可选，`00` 第 11 项）。

## 三、每个阶段结束前

自动化测试通过，新功能有对应测试；前端冒烟脚本通过（放在 `tools/`）。

## 四、测试

| 层次 | 测什么 | 怎么测 |
| --- | --- | --- |
| 单元 | 解析、协议解码、步数累计、稳定性分类 | JUnit，脱敏假数据 |
| 集成 | 入库、`MERGE` 时间新旧、去重、分区、视图 | 本机 Oracle 专用测试用户 |
| 接口 | 成功、无权限、参数错误、无数据 | MockMvc |
| 端到端 | 页面打开、图表数量、无控制台报错、点击交互 | Playwright 冒烟脚本 |
| 数值复算 | 页面数字 = SQL 复算 | 测试里写好对照 SQL |
| 稳定性 | 200 块手表持续上传、缓冲不积压 | 手表模拟器跑数小时 |

## 五、风险

| 风险 | 应对 |
| --- | --- |
| 真实手表行为与协议不符（老项目有先例：文字下发无回应） | 阶段 7 真实手表验证；模拟器只能证明我们的代码符合协议 |
| CAD 转换质量（转换工具报过"不稳定对象"警告） | 阶段 4 转换后和 CAD 原图对照，你来看 |
| 手表规模超过 200 块（如 1000 块） | 缓冲和分区设计可承受。阶段 2 本机压测过 1000 块表、60 倍的上报频率：写库跟得上，一天的日汇总重算约 2.2 秒（`03` 第九节）；上线服务器到阶段 7 再测 |
