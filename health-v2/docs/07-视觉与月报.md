# 07 视觉规范与月度汇总报告

## 第一部分：视觉规范

### 一、风格

深色科技风：近黑背景，青绿色发光的线条和数字，半透明玻璃质感的面板，面板四角有细边框装饰。**布局和视觉与参考截图几乎一致**（位置和尺寸见 `09`）；图片素材（首页动画、报告插画、图标）按相近风格自己绘制。

### 二、颜色

颜色定义成 CSS 变量，集中放 `styles/tokens.css`，组件里不写死颜色值。

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--bg-page` | `#030d0c` | 页面底色 |
| `--bg-panel` | `rgba(6, 40, 36, 0.55)` | 面板背景 |
| `--bg-panel-strong` | `rgba(4, 28, 25, 0.85)` | 表头、弹窗背景 |
| `--border-glow` | `rgba(29, 233, 182, 0.35)` | 面板边框、装饰线 |
| `--accent` | `#19e6b0` | 主强调：大数字、选中态、按钮 |
| `--accent-soft` | `#14b8a6` | 次强调：图表面积、图标 |
| `--text-primary` | `#d8fff5` | 主要文字 |
| `--text-secondary` | `#7fb8ab` | 次要文字 |
| `--warn` | `#ffb020` | 警告、数据较旧 |
| `--danger` | `#ff4d4f` | 告警、故障 |
| `--info` | `#2db7f5` | 次要按钮 |

告警除颜色外要配图标或文字（色弱用户分不出红绿）。

### 三、字体

矿上是内网，字体文件必须放在项目里，不用 Google Fonts 或 CDN。

| 用途 | 字体 |
| --- | --- |
| 正文 | 思源黑体（Noto Sans SC），开源可商用 |
| 大屏标题 | 思源黑体 Bold + 斜体变换（CSS `skew`）+ 渐变色 |
| 大数字 | Orbitron 或 Share Tech Mono，开源可商用 |

中文字体要子集化（只保留常用汉字，woff2 格式，控制在 2 MB 内）。

### 四、布局

设计稿固定 **1920 × 1080**，各区域用比例布局（换算方法见 `09` 第一节），运行时按窗口大小等比缩放（CSS `transform: scale()`），比例不一致时居中留黑边。最小支持 1366 × 768，不支持手机。

实现上的约定（阶段 3）：

- 颜色只用 `styles/tokens.css` 的变量；阶段 3 新增的变量（入口页、主区域、弹层、曲线等）取自截图 1、13、16 的实际像素颜色。
- 页面按 1920×1080 画布的绝对坐标布局：`ScreenLayout` 的主区域铺满画布，各页面把 `09` 里的参考坐标换算后直接写在样式里（注释里留着原始坐标）。页面逻辑放同目录的 `use-*-page.ts`。
- `CounterRoll`：每一位是一列 0–9，数值变化时 600 ms 滚过去；第一次显示不滚；`null` 显示"暂无数据"。`boxed` 是"累计采集数据"的数字牌样式。
- 面板数据统一用 `composables/use-polling.ts`：第一次加载骨架屏，失败时保留上次数据并在角落写"刷新失败"，从没成功过显示"加载失败"。

阶段 5 的约定：

- `BodyModel3D`：three.js 体积大（打包后单独一个约 620 KB 的分包），页面用 `defineAsyncComponent` 引入，切到个人档案时才下载 three.js 和模型 `human_body_wireframe.glb`。材质和首页动画同一套全息着色（`tools/hero-render/scene.js`），站在 three.js 画的发光圆形平台上；相机按截图 4 取景（人体在主区域里的上下位置、平台宽约 490 px）。颜色取自 `tokens.css` 的 `--body-*` 变量。
- `BodyModel3D` 的生命周期：`paused`（切到"预警记录"标签）、页面切到后台时停止逐帧绘制，恢复后接着画；"减少动态效果"时不自转、只画静止的一帧。卸载时停掉动画、移除监听、释放全部几何体/材质/贴图、`forceContextLoss()` 释放 WebGL 上下文并移除 canvas；模型还没下载完就离开的，下载完立即释放。根元素的 `data-state`（`loading` / `ready` / `error`）供冒烟脚本判断。
- 反复进出个人档案的实测（生产构建，本机 Chrome + Metal）：每次离开都释放 WebGL 上下文；DOM 节点、事件监听回到同一个数；JS 堆前十几次缓慢上涨约 2 MB 后不再增长（20 次稳定在 11.0 MB），是浏览器的代码缓存，不随次数增长；模型第一次就绪约 0.2 秒，之后约 0.09 秒；自转时 60 帧/秒，最长一帧 17 毫秒。冒烟脚本每次运行都检查（`tools/dev/frontend-smoke.mjs` 的个人档案）。测内存时等元素要用 `locator().waitFor()`，Playwright 的 `waitForSelector` 返回的元素句柄会让浏览器一直留着整页，测出假的泄漏。

### 六、动画

| 动画 | 说明 |
| --- | --- |
| 数字滚动 | 600 ms，只在数值变化时 |
| 面板入场 | 首次进入时依次淡入，间隔 60 ms |
| 首页中央 | 预渲染循环视频 |
| 3D 人体 | 缓慢自转，拖动时暂停 |
| 背景扫描线 | 极淡、很慢 |

性能：同一页面最多同时播放一个视频；页面切到后台时暂停动画；系统开启"减少动态效果"时关闭装饰动画，只保留数据刷新。

### 七、首页中央动画

预渲染成循环视频，浏览器只播放。工具在 `tools/hero-render/`（阶段 3 已做）：

1. 用 three.js 搭场景（`scene.js`）：全息人体、发光圆形平台、旋转光环、上升光点、四个悬浮方形平台。两个场景：
   - `dashboard`：动态数据页主区域，1690×708（主区域 1352×566 放大 1.25 倍）。四个平台按页面文字的位置反算到地面上摆放，图标依次是心率、血氧、体温、血压，和 `DisplayStage.vue` 的文字一一对应；改了文字位置要重新渲染。
   - `portal`：入口页圆环里，720×720，人体站在圆形平台上，周围三道倾斜光环。
2. 人体模型用老项目的 `human_body_wireframe.glb`（全息线框人体，复制到 `frontend/public/models/`，阶段 5 的 `BodyModel3D` 也用它）。老项目还有 `holograming_man.glb`、`wireframe_man.glb`，按统一的缩放和朝向渲染出来不是一个站立的完整人体，没选。材质统一换成全息着色（边缘亮、横向细线、一道从下往上的扫描带）。
3. `render.mjs` 用 Playwright 打开本地页面，逐帧调用 `heroFrame(t)` 截图（30 帧/秒 × 8 秒 = 240 帧），ffmpeg（libx264）合成 H.264 mp4。所有动画都是周期能整除 8 秒的函数，第 0 帧和第 8 秒完全相同，循环无缝。实际大小约 1.4 MB（比原来估计的 3–5 MB 小）。本机 ffmpeg 用 Homebrew 安装。
4. 视频背景纯黑（合成时用曲线把接近黑的底压成纯黑），页面上用 CSS `mix-blend-mode: screen` 融掉黑色。
5. 同时导出静态海报图（第 0 帧，jpg），视频加载前和"减少动态效果"模式下显示。
6. 输出到 `frontend/src/assets/hero/`（`dashboard.mp4`、`portal.mp4` 和两张海报）。重新渲染：`node tools/hero-render/render.mjs --scene=dashboard`（或 `portal`）；`--scene=preview --still=a.png` 只截一张图看模型。
7. 四个平台上的名称和数字是页面文字，叠在视频上（数字会变）。入口页圆环外圈的发光双环、蓝色弧段、虚线圈是页面上的 SVG，视频只放在圆环里面。

## 第二部分：月度汇总报告

### 一、形态

在动态数据页点"月度汇总"，全屏弹出一本书：

- 鼠标移到页面右下角，页角微微卷起；点击或拖动翻页。键盘 ← → 翻页，`Esc` 关闭，右上角有关闭按钮。页码 `n / 13` 显示在页面角落。
- 顶部有月份选择，默认上个月，只列有数据的月份。
- 技术：StPageFlip，封面单页，后面双页展开；页面是 HTML，图表用 ECharts。
- 配色与大屏不同，是纸质文档感：白底蓝色，页眉蓝色渐变，标题栏深蓝斜切条，正文深灰。

### 三、计算口径

统计范围是所选月份的自然月。

**第 3 页**：涉及职工 = 本月在 `POS_PRESENCE_DAILY` 里至少有一天入井记录的不同人数；涵盖工种 = 这些人里不同工种的个数（"未设置"不算）；饼图按工种统计人数，取前 8 种，其余合并为"其他"，工种未录入的单独一类。

**第 4 页**：使用手表的人 = 本月在 `HEALTH_DAILY_SUMMARY` 有记录的不同人数；涉及部门 = 这些人所属的不同部门数；饼图按部门取前 8 其余合并，表格显示前 8 行加"合计"。

**第 5 页**：月最大 = 各日最大值中的最大；月最小 = 各日最小值中的最小；月平均 = 按每天样本数加权的平均。

**第 6 页**：六类告警各自的涉及人数（去重）和事件数；一共没有则显示"本月暂无告警数据"。

**第 8–10 页 稳定状态评估**（建议方案，需矿上医务人员确认，`00` 第 10 项）：

方法对所有岗位相同，下面的数字按**岗位类别**分别配置（存在 `ALERT_RULE` 和 `JOB_GROUP` 里，没配的岗位用默认类别的值）。表里写的是默认类别的建议值。

每个人本月某指标的**正常率** = 落在正常范围内的样本数 ÷ 总样本数（正常范围按这个人所属**岗位类别**的阈值，和实时告警用同一套，见 `03` 第四节；已存在 `NORMAL_COUNT` 里）。干重活的岗位用它自己的正常范围，不会因为心率本来就高被判成"不稳定"。

| 状态 | 条件 |
| --- | --- |
| 稳定 | 正常率 ≥ `STABLE_PCT`（建议 90%） |
| 波动 | `UNSTABLE_PCT` ≤ 正常率 < `STABLE_PCT` |
| 不稳定 | 正常率 < `UNSTABLE_PCT`（建议 70%） |

本月该指标有数据的天数少于 `MIN_EVAL_DAYS`（建议 5 天）的人不参与评估，页面注明"有 X 人因数据不足未参与评估"。页面内容：三种状态的人数（饼图）+ "不稳定"人员表（姓名、部门、岗位类别、正常率、最小值、最大值，前 10 人）。

**第 11、12 页 运动量**：每人本月日均步数 = 总步数 ÷ 有步数记录的天数；只统计有 5 天以上记录的人（否则只戴一天的人会排到"较小"第一名）；各取前 10；排行条长度以"较大"页的第一名为基准，两页用同一把尺。

**第 13 页 风险职工**（建议方案，需确认）：满足任意一条列入：① 本月六类告警（`CATEGORY` 不是 `OTHER`）的事件 ≥ `RISK_EVENT_COUNT` 条（按岗位类别配置，默认建议 3 条；低电、脱落等设备事件不算；一条事件是一段持续的异常，不跨天，见 `03` 第四节）；② 心率、血氧、体温任一项被评为"不稳定"。表格：姓名、部门、告警次数、主要问题（如"心率不稳定；血氧偏低告警 5 次"）。没有符合条件的显示"本月暂无需要重点关注的职工"。

**计算时用哪个岗位类别**：用生成报告时这个人所属的类别。月中换了工种的人，整月按新类别算（`NORMAL_COUNT` 里每天用的类别记在 `RULE_GROUP`，可以查）。

**AI 提示**（可选功能，阶段 8，`00` 第 11 项）：本地大模型看这个月的数据，把"曲线形状不太寻常、建议医生看一看"的人列出来，写一句理由。它只是提示，不是结论：

- 单独放在结论页下方，标题写"AI 提示（仅供医生参考，不作为评估结论）"；
- 不改变稳定性评估和风险职工名单，不计入任何统计数字；
- 名单和理由原样保存，同一份月报再打开看到的内容不变。

### 四、接口

`GET /api/report/months` → 有数据的月份，如 `["2026-08", "2026-09"]`。

`GET /api/report/monthly?month=2026-08`：

```json
{
  "month": "2026-08",
  "overview":   { "workerCount": 647, "jobKindCount": 32,
                  "byJobKind": [ { "name": "井下电钳工", "count": 112, "percent": 17.3 } ] },
  "watchUsage": { "userCount": 47, "deptCount": 8,
                  "byDept": [ { "name": "机运工区", "count": 14, "percent": 29.79 } ] },
  "vitals":     { "HEART_RATE": { "max": 161, "min": 42, "avg": 80.9 },
                  "TEMPERATURE": { "max": 37.6, "min": 36.1, "avg": 36.6 },
                  "SPO2": { "max": 99, "min": 84, "avg": 94.9 } },
  "alerts":     { "byCategory": [ { "category": "HEART_RATE", "persons": 3, "events": 7 } ] },
  "stability":  { "HEART_RATE": { "stable": 40, "fluctuating": 5, "unstable": 2, "notEvaluated": 0,
                                  "unstableList": [ ] } },
  "steps":      { "low": [ ], "high": [ ], "minDays": 5 },
```
