# 05 页面与接口

**所有数字由后端算好，前端只负责显示。** 页面的布局位置和样式见 `09`，本文里的示意图只表示大致结构。

## 一、页面

前端用 hash 路由，如 `/#/dashboard`。

| 路由 | 页面 |
| --- | --- |
| `/login` | 登录页（沿用老项目的登录页，复制后独立使用）。`LOGIN_SHOW_DEFAULT_ACCOUNT` 为 `true` 时，登录框下方明文提示"默认账号 admin，密码 admin"，提示内容由后端 `GET /api/auth/login-hint` 返回（不需要登录），为 `false` 时返回空、页面不显示 |
| `/portal` | 入口页，登录后默认进入 |
| `/dashboard` | 动态数据（大屏）：展示模式（默认）、地图模式（`?mode=map`） |
| `/archive` | 健康档案（人员卡片列表） |
| `/archive/:cardCode` | 个人档案 |
| 弹层 | 月度汇总（翻书）、佩戴情况（确认后下载 Excel） |

顶部导航：动态数据 · 健康档案 · 账号菜单（退出登录；"数据管理"暂未开放，点击提示"建设中"）。

## 二、通用规则

**面板状态**：每个面板要处理四种状态。

| 状态 | 表现 |
| --- | --- |
| 加载中 | 骨架屏，不闪 `0` |
| 没有数据 | 显示"暂无数据" |
| 未录入 | 显示"未录入"（如没有年龄） |
| 刷新失败 | 保留上次数据，面板角落写"刷新失败，显示的是 hh:mm 的数据" |

后端拿不到的数据返回 `null`，前端据此显示"暂无数据"或"未录入"，不显示 `0`。

**数据新鲜度**：定位数据超过过期阈值（见 `01` 配置表）没更新，页面顶部显示黄色横幅"定位数据已过期，最后更新 hh:mm"，页面角落常驻显示定位数据时间和手表数据时间。

**刷新**：动态数据和地图模式每 30 秒（手动刷新与自动刷新共用一个倒计时，不并发重复请求）；个人档案 60 秒；健康档案列表不自动刷新。

**人员编号**：卡编码 17 位，页面表格和卡片显示"卡号"（后 5 位），悬停显示完整 17 位；Excel 导出和接口用完整 17 位。

**接口**：路径以 `/api` 开头；除登录外都要登录，令牌放请求头 `satoken`；返回格式和分页见 `01`；带数据时间的接口返回 `dataTime`（数据自己的时间）。

### 展示模式

`GET /api/dashboard/overview`：

```json
{
  "dataTime": "2026-09-24 10:13:19",
  "totalCollected": 6471495,
  "collected": { "HEART_RATE": 5219387, "SPO2": 602780, "TEMPERATURE": 649328, "BLOOD_PRESSURE": 0 },
  "alerts": { "SOS": 0, "FALL": 0, "HEART_RATE": 0, "BLOOD_PRESSURE": 0, "SPO2": 0, "TEMPERATURE": 0 },
  "alertWindow": "today",
  "deviceEventCount": 3
}
```

| 内容 | 口径 |
| --- | --- |
| 累计采集数据（大数字） | `METRIC_COUNTER` 各指标累计条数之和 |
| 心率 / 血氧 / 体温 / 血压（四个平台） | 各自累计条数 |
| 左侧"佩戴情况" | 确认框 → 下载 Excel（见下） |
| 左侧"月度汇总" | 打开翻书报告（`07`） |

### 右侧：六类告警

SOS、跌倒、心率、血压、血氧、体温。口径：`ALERT_EVENT` 里 `LAST_OCCURRED_AT` 在今天 0 点之后、对应 `CATEGORY` 的**人数**（同一个人多条事件算 1 个）。

手表未绑定时，事件没有卡编码，按设备号算 1 个"人"，点开显示"未绑定设备 + IMEI"。这样未绑定的手表发出 SOS 也能在大屏上看到（`03` 第二节）。

### 右侧：设备事件

"体征信息展示"面板标题栏右侧有一个"设备事件 N"标记，N 是今天的设备事件条数：`ALERT_EVENT` 里 `SRC = 'DEVICE'`、`CATEGORY = 'OTHER'`、`LAST_OCCURRED_AT` 在今天 0 点之后的事件数（低电、脱落、佩戴提醒、拆卸、红外等；SOS 和跌倒已经在格子里，不重复算）。一段持续的事件只算一条（去重规则见 `03` 第四节）。N 为 0 时标记显示"设备事件 0"，不隐藏。

点标记弹出列表 `GET /api/dashboard/device-events?page=1&size=20`，最新的在前：

| 列 | 说明 |
| --- | --- |
| 姓名、卡号 | 未绑定的手表写"未绑定设备"和 IMEI |
| 事件 | 低电、脱落、佩戴提醒、拆卸、红外…… |
| 时间 | 最近一次发生时间；重复发生的写次数，如"3 次" |

### 右侧：重点人员

`GET /api/dashboard/key-persons`：重点监护名单里的人，每行姓名、卡号、部门、"详情"（跳转个人档案）。为空显示"暂无重点人员"。

### 底部左：上线职工曲线

`GET /api/dashboard/headcount-series?date=2026-09-24`：横轴当天 0 点到现在，纵轴井下人数，数据点来自 `POS_HEADCOUNT_SERIES`（每份定位文件一个点）。没有数据的时段不画点、不连线。曲线画井下人数还是已上线人数，见 `00` 第 19 项。

### 底部中：人员信息展示

`GET /api/dashboard/headcount`：

```json
{
  "inWell": 31, "expected": 8, "online": 1, "offline": 7,
  "onlineNormal": 1, "onlineAlert": 0,
  "positioning": { "dataTime": "2026-09-24 10:13:19", "stale": false }
}
```

| 名称 | 口径 |
| --- | --- |
| 井下职工 | `V_POS_IN_WELL` 的人数 |
| 应上线 | 井下职工中绑定了手表的人数 |
| 已上线 | 应上线中手表在线的人数（在线口径见 `03` 第五节） |
| 未上线 | 应上线 − 已上线 |
| 已上线无告警 / 已上线告警 | 已上线中，当前没有 / 有**仍在发生**的六类告警的人数 |

关系：已上线无告警 + 已上线告警 = 已上线。

**仍在发生** = 这个人有六类告警事件的 `LAST_OCCURRED_AT` 在最近 30 分钟内（`ALERT_ACTIVE_MINUTES`，见 `01` 配置表）。体征恢复正常后不再产生新的异常，30 分钟后他自动回到"已上线无告警"。这和上面六个格子不同：格子统计今天一共有多少人出过事，这里只看现在。

**人员表** `GET /api/dashboard/in-well-persons?keyword=&page=1&size=20`：

| 列 | 来源 |
| --- | --- |
| 姓名 | `POS_PERSON.PERSON_NAME` |
| 卡号 | 卡编码后 5 位 |
| 机构 | 部门，没有则"未录入" |
| 区域 | 所在区域名称（`POS_AREA`） |
| 监测 | 图标：手表在线 / 离线 / 未绑定 |

点击某一行：切换到地图模式并定位到这个人。

### 底部右：实时运动量

`GET /api/dashboard/steps-rank?limit=10`：今天步数最多的前 N 人（`STEP_DAILY`）。今天有步数记录的人都列出，记录为 0 的显示"0 步"；今天没有记录的人不列。

### 佩戴情况导出

对比"定位系统说在井下的人"和"手表实际上传了数据的人"。点"佩戴情况" → 确认框"此操作将导出下井职工前一天手表佩戴情况" → 下载 Excel。

`GET /api/export/wear?date=2026-09-23`（默认昨天）：

- 文件名 `佩戴情况_yyyyMMddHHmmss.xlsx`，工作表名 `数据上报记录`。
- 列：统计日期、人员卡编码（完整 17 位）、姓名、部门（没有则"未录入"）、上报数据。
- 名单：`POS_PRESENCE_DAILY` 里那天有入井记录、且绑定了手表的人。"那天"怎么算见 `04` 的 `POS_PRESENCE_DAILY`。
- 上报数据：那天 `HEALTH_RECORD` 有该人记录写"数据上传正常"，否则写"数据未上传"（是否只看井下时段见 `00` 第 20 项）。

## 五、地图模式

**交互**：

- 左侧入口：重点监护、今日关注（只显示名单里的人，再点一次取消过滤）。
- 顶部搜索框：输入姓名或卡号回车定位；旁边有刷新按钮。
- 点人员图标或列表里的人：地图移到他所在的基站，弹出体征卡。

**人员怎么画**：

| 情况 | 表现 |
| --- | --- |
| 所在基站已摆放 | 在该基站位置画人员图标 |
| 多人在同一基站 | 合并成一个图标显示人数，点开展开成列表 |
| 所在基站未摆放 | 地图上不画；列表里显示区域名称，标"基站未摆放" |
| 不在井下 | 不画 |

**体征卡**：

| 内容 | 说明 |
| --- | --- |
| 姓名、卡号、部门 | |
| 位置 | 区域名称 + 基站名称 + 定位时间，写"xx 基站附近" |
| 心率、体温、血氧、血压 | 每项带采集时间，超过"数据较旧"阈值（见 `01` 配置表）没更新的标灰并写"数据较旧" |
| 电量 | 来自心跳，带时间 |
| 手表状态 | 在线 / 离线（最后在线时间）/ 未绑定 |
| 按钮 | "告警记录"（展开最近 3 条）、"档案"（跳个人档案） |

**接口**：

| 接口 | 用途 |
| --- | --- |
| `GET /api/map/config` | 底图配置：WMS 地址、图层名、坐标系、地图范围 |
| `GET /api/map/persons?filter=…&keyword=…` | 井下人员及位置；`filter` 取 `all` / `key`（重点监护）/ `today`（今日关注） |
| `GET /api/map/persons/{cardCode}/card` | 体征卡内容 |
| `GET /api/map/stations` | 全部基站（是否已摆放、坐标、名称） |
| `PUT` / `DELETE /api/map/stations/{stationCode}/mark` | 摆放/修改、删除摆放（规则见 `06`） |
| `GET /api/map/station-logs?stationCode=&page=` | 摆放操作日志 |

`GET /api/map/persons` 每个人：

```json
{ "cardCode": "62082300920310025", "name": "…", "areaName": "下口区域",
  "stationCode": "6208230092030008000012", "stationName": "新副井下口1",
  "placed": true, "x": 39482000.0, "y": 3852000.0,
  "posTime": "2026-09-24 10:13:15", "watchState": "ONLINE" }
```

## 六、健康档案

- 筛选：部门（下拉）、工种（下拉，可搜索）、姓名/卡号（输入框）、"查询"、"重置"。
- 卡片网格每页 12 张（4×3），左右箭头翻页。卡片：默认头像、姓名、卡号、工种、部门、年龄（未录入显示"未录入"）、"健康档案"按钮。
- 数据源 `POS_PERSON`，默认只显示绑定了手表的人（`00` 第 8 项）。

接口：`GET /api/archive/filters` → `{ depts, jobKinds }`；`GET /api/archive/persons?dept=&jobKind=&keyword=&page=1&size=12`。

## 八、其他接口

**名单**：`GET /api/watch-list?type=KEY`；`POST /api/watch-list`（`{ cardCode, type, note }`）；`DELETE /api/watch-list/{id}`。加入入口在个人档案右上角"加入重点监护 / 今日关注"，再点一次移出。名单只靠人工加入，系统不按告警或其他规则自动加人。"重点监护"一直有效，直到有人移出；"今日关注"当天 24 点自动失效。加入、移除都写操作日志（`WATCH_LIST_ADD` / `WATCH_LIST_REMOVE`）。

**月报**：`GET /api/report/months`、`GET /api/report/monthly?month=2026-08`，见 `07`。

**运维**：`GET /api/positioning/status`（每种定位文件最后一次的处理情况、数据时间、是否过期）；`GET /actuator/health`（顶层 `status` 为 `UP` 才算可用）；`GET /actuator/metrics`。

**登录**：`GET /api/auth/login-hint`（登录页提示，不需要登录）；`POST /api/auth/login`（`{ username, password }` → `{ token, user }`）；`POST /api/auth/logout`；`GET /api/auth/me`。所有登录用户权限相同。账号在后台管理做出来之前由脚本创建。

**登录锁定**：同一个用户名连续输错 5 次密码，锁定 10 分钟，这期间密码对了也不让登录，提示"密码错误次数过多，请 10 分钟后再试"。失败次数存在 Redis 的 `hv2:auth:fail:<用户名>`：每错一次加 1，第一次出错时设 10 分钟后自动过期（10 分钟内累计不到 5 次，计数自动清零）；第 5 次出错时把过期时间重新设为 10 分钟，保证每次锁满 10 分钟；登录成功就删掉。所以锁定到期后自动解除，不用改 `SYS_USER` 表，后端重启也不影响。用户名不存在也照样计数，提示语和"密码错误"一样，不让人借此猜出哪些用户名存在。
