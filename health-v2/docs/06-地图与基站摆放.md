# 06 地图与基站摆放

## 一、要解决的问题

地图模式要在巷道图上显示"某某在哪"。定位数据只告诉我们每个人**离他最近的基站**，基站有**名字**，但**没有可用坐标**。所以要做两件事：

1. 把矿上的 CAD 图变成网页能显示的底图；
2. 让用户在底图上手动点出每个基站的位置（摆放）。摆好后，"某某在某基站"就能画成图上的一个点。

## 二、坐标系

地图统一用 **EPSG:4527**（CGCS2000 / 3 度带高斯投影，第 39 带，中央经线 117°E）。带号核对过：样例文件头里的矿井位于约 117°E、34.8°N，和 CAD 坐标"第 39 带、北向约 3852 km"一致。图上和数据库里的坐标都是 CAD 图上的原始数字：东向 `39482000`（8 位，带 `39` 带号前缀），北向 `3852000`（7 位），单位米。

CAD 图的基准是 2000 还是西安 80，从图上看不出（见 `00` 第 16 项）。有一条线索：四网融合系统的接口规范（`reference/four-net/docs/` 里的 `.doc`，阶段 4 读过）写着"GIS 坐标系采用西安 80，设备位置用 (X, Y, Z) 表示"，说明厂家那套系统按西安 80 用这张图，但这仍不能证明 CAD 本身的基准。对本功能没有影响：基站是用户在这张底图上点出来的，两者用同一套数字；我们不把这些坐标和卫星地图、GPS 等外部数据叠加。日后要叠加外部数据时再处理基准。

前端用 proj4 注册：

```text
EPSG:4527 = +proj=tmerc +lat_0=0 +lon_0=117 +k=1 +x_0=39500000 +y_0=0 +ellps=GRS80 +units=m +no_defs
```

**轴顺序的坑**：EPSG:4527 官方轴顺序是"先北后东"，而 CAD 图和我们的数据是"先东后北"。WMS 1.3.0 会按官方顺序理解坐标，底图会整个错位或空白。**前端请求 GeoServer 一律用 WMS 1.1.1**（永远先东后北），并在代码注释里写明原因。阶段 4 实测：同一个范围 `39480087.9,3851797.4,39489391.2,3854743.4`，用 1.1.1 请求画出 23980 个有颜色的像素，用 1.3.0 请求一个都没有（整张空白）。

**坐标系要设范围**（`10` 第 7 项，阶段 4 核对）：OpenLayers 注册 EPSG:4527 后，如果不给它设范围（`projection.setExtent`），它按"全世界"建默认网格：原点附近正负 20037508 米，而我们的东向坐标约 39480000，根本不在网格里，瓦片请求不会发出；缩放级别也按全世界算，第 0 级一个像素 156 公里。所以前端注册坐标系后，立刻把它的范围设成 `/api/map/config` 返回的地图范围（`frontend/src/views/dashboard/map/mine-map.ts`）。设了以后第 0 级是一个像素 36 米。

## 三、底图制作

CAD 文件 14.5 MB，但真正画出来的只有约 2 万个对象（48 个图层，2117 条文字）；文件里另有约 26 万个对象是从没被用到的图块定义，不显示，之前统计的"11 万条线、5.8 万条文字、113 个图层"把它们也算进去了（阶段 4 用原图核对，`10` 第 6 项）。选进底图的巷道线约 6300 条，浏览器直接画也会卡，所以仍在服务器上渲染成图片，浏览器只拼图片，这就是 GeoServer 的作用。

```text
矿上的 CAD 图 (.dwg)
   │ ① dwg2dxf（libredwg）转成 DXF
   │ ② 挑选图层，转成 GeoPackage（ogr2ogr / GDAL）
   │ ③ 发布到 GeoServer，配样式
   ▼
GeoServer ──WMS 1.1.1──▶ 前端 OpenLayers
```

- **GeoServer**：读地图数据，按请求的范围和缩放画出图片返回的软件；**GeoPackage** 是单文件的地图数据格式；**DXF** 是 CAD 的开放交换格式（DWG 是二进制，工具读不了）。
- **① 转 DXF**：LibreDWG 的 `dwg2dxf`（文件是 AutoCAD 2004 格式 `AC1018`）。DXF 里的中文是 GBK 编码（文件头 `$DWGCODEPAGE = ANSI_936`），GDAL 按文件头自动转换，不用另外指定。转换时会报几个"Unstable Class"警告，GDAL 读图块时有 8 处解析错误，都在没被用到的图块定义里，不影响图上的内容。
- **一张图纸上并排三幅图**：左边是地质和地面平面图（钻孔、河流、村庄、井田内的老采区，真实坐标）；中间带图框的是通风系统图，**巷道都在这里，但整幅图偏离了真实坐标**；右边还有一幅（避灾路线等）。厂家四网融合系统用的巷道层（`reference/cad/zsl_line2`、`zsl_text`）就是把中间那幅平移 **(-11633.321, +988.923) 米**得到的，没有旋转缩放：按这个平移量，厂家 83% 的顶点和 CAD 的顶点在 1 厘米内重合，画成图 99.5% 的线重合，也正好落在左边平面图的老采区上；112 条文字位置完全相同。我们照样平移，底图坐标和厂家系统、和本节开头写的坐标范围一致。
- **② 挑选图层**：113 个图层里很多是地质、钻孔、等值线，与"人在哪条巷道"无关。先出一份图层清单（名称、实体数量、类型、预览图），**由你挑选**。可能相关的有煤巷、岩巷、巷道注记、工作面注记、避灾路线、通风符号，以预览为准。转成两个图层：**线**（巷道轮廓）和**文字**（巷道、工作面名称）。
- **② 已挑定（`00` 第 1 项）**：巷道线用岩巷、煤巷、9煤煤巷、7煤煤巷、井筒和带 `ZSLK0900DCJ`/`ZSLK0700DCJ` 的几层，共 6331 条；文字用巷道名称、岩巷道名、防尘、井筒（和煤巷里的一条），共 112 条，和厂家选的一样。厂家还带了 `0`、`月末色框` 两层的一部分和 `溜煤眼`，我们没要，需要时改 `build.py` 的名单重跑即可。成品是 `mine-map.gpkg` 的两张表 `roadway_line`（`layer`、`color`）和 `roadway_label`（`layer`、`text`、`size` 字高、`angle` 角度）。做法和脚本见 `tools/map-prep/README.md`，一条命令 `tools/map-prep/prepare.sh` 跑完（约 7 秒），输出在 `runtime/map-prep/`（矿上的图纸，不提交）。GDAL 用官方 Docker 镜像 `ghcr.io/osgeo/gdal:ubuntu-small-3.13.3`，不装在本机。
- **③ 发布**：GeoServer 用官方 Docker 镜像 `docker.osgeo.org/geoserver:2.28.5`（只有 Intel 版本，Mac 上转译运行，部署到矿上的 Linux 服务器时是原生的），线和文字各配一个样式（深色底）。CAD 里的颜色是给白纸用的（煤巷黑色、岩巷棕色），深色底上看不见，所以按图层类别上色、对照截图 14：煤巷类绿色、岩巷类橙色、井筒等灰蓝色。
- **③ 阶段 4 的做法**：
  - 镜像：官方镜像只有 DejaVu 字体，所以在它上面加装中文字体，做成本项目的镜像 `hv2-geoserver:2.28.5`（`tools/dev/geoserver/Dockerfile`）。字体用文泉驿微米黑（`fonts-wqy-microhei`，约 5 MB）：它是 TrueType 轮廓，Java 能直接画；思源黑体这类 CFF 轮廓的字体 Java 支持得不好。
  - 容器：`tools/dev/docker-compose.yml` 里的 `geoserver` 服务，容器名 `hv2-geoserver`，只对本机开放 `127.0.0.1:8082`，转译运行约 15 秒启动。`runtime/map-prep/` 只读挂进容器；管理员密码在 `.env.local` 的 `GEOSERVER_ADMIN_PASSWORD`（不用镜像默认的 `geoserver`）。
  - 发布：`tools/map-prep/publish.sh` 用 GeoServer 的 REST 接口，删掉工作区 `hv2` 再重建（可以反复运行）：数据源 `mine_map`（GeoPackage，只读）、图层 `hv2:roadway_line` 和 `hv2:roadway_label`（EPSG:4527）、样式 `tools/map-prep/styles/*.sld`。重新生成 `mine-map.gpkg` 后再跑一次。
  - 颜色：煤巷类 `#62c64a`（煤巷、9煤煤巷、7煤煤巷、带 `ZSLK` 的两层煤巷），岩巷类 `#d9963f`（岩巷、岩巷ZSLK0900DCJ），其余（井筒、设计巷道、进尺、回采工作面、回采月份）灰蓝 `#8fb0c6`；线宽 1.6 像素。
  - 巷道名称：白底黑字，按 CAD 里的角度沿巷道摆放（CAD 的角度是逆时针，SLD 是顺时针，取负；90°–270° 之间的字会倒着，再转 180°）。白底用 12 像素字加 3.5 像素的白色光晕做出来：中文笔画密，光晕连成一片，看起来就是白色小标签。比例尺小于 1:60000（整个井田约 1:25000）时不画字；互相压住的字由 GeoServer 自动去掉，放大后才都显示出来。
  - 浏览器不直接连 GeoServer：前端开发服务器把 `/geoserver/hv2/wms` 转给 8082（`frontend/vite.config.ts`，上线时 nginx 做同样的转发），只转 WMS，GeoServer 的管理页面和 REST 接口不对浏览器开放。WMS 地址由 `/api/map/config` 返回（配置 `MAP_WMS_URL`，见 `01`）。底图图片不需要登录就能取（浏览器用 `<img>` 取图，带不上 `satoken` 请求头）；矿上是内网，目前这样够用。要限制时，上线的 nginx 可以先问一下后端令牌是否有效再转发（阶段 7 部署时定）。
- **地图范围**不用 DXF 文件头里的 `EXTMIN`/`EXTMAX`（它把图纸外的杂物也算进去，范围偏大），而是选好图层后按实际数据计算，存进地图配置（`application.yml` 的 `hv2.map.extent`）。按选好的巷道线算是 `39480087.9, 3851797.4 – 39489391.2, 3854743.4`（东西约 9.3 公里、南北约 2.9 公里）。

已知的坑：

| 坑 | 应对 |
| --- | --- |
| GeoServer 的 Docker 镜像没有中文字体，文字显示成方块 | 镜像里装中文字体，样式里指定字体名 |
| DXF 中文是 GBK | 转换时显式指定编码，转完抽查几条中文 |
| 实体多（选中的巷道线约 6300 条，最多的岩巷一层约 5000 条） | GeoPackage 建空间索引；样式按比例尺控制，缩小时不画文字。实测转译运行下画整个井田一张图不到 1 秒 |
| 文字底板不跟着旋转：GeoServer 用"图形拉伸当底板"（`graphic-resize`）时，所有文字都变成横的 | 不用底板，改用白色光晕做白底（见上） |
| SLD 里的函数参数要写成函数形式（如 `greaterThan`），写成过滤条件（`PropertyIsGreaterThan`）会让样式上传报 500 | 已按函数形式写 |

## 四、前端地图

OpenLayers + proj4。图层从下往上：

| 层 | 内容 | 来源 |
| --- | --- | --- |
| 1 | 巷道线 | GeoServer WMS 1.1.1 |
| 2 | 巷道文字 | GeoServer WMS 1.1.1 |
| 3 | 基站图标 | 我们的接口，前端矢量图层 |
| 4 | 人员图标 | 同上 |

基站和人员只有几百个点、每 30 秒变一次，直接在前端画，可点击、可拖动，不放进 GeoServer。

阶段 4 的做法（`frontend/src/views/dashboard/map/`）：

- 底图用"整张图"方式请求（OpenLayers 的 `ImageWMS`，比屏幕大 1.5 倍），不用瓦片：巷道名称不会在瓦片边上被切断或重复。线和文字是两次请求。
- 打开时整个井田铺满主区域（约 7 米/像素）；最多放大到 0.08 米/像素，最多缩小到 16 米/像素；地图可以拖出范围 600 米，免得边上的巷道贴着屏幕边。
- 底图请求失败时地图上方提示"底图加载失败（GeoServer 没有响应），人员和基站照常显示"，下一次加载成功后自动消失。
- 地图代码（OpenLayers、proj4，约 450 KB）在切到地图模式时才加载，展示模式不加载。

| 对象 | 样式 |
| --- | --- |
| 基站 | 小图标，通讯正常（青绿）/ 中断（灰）/ 故障（红）；还没收到状态的也是灰。比 4 米/像素粗时不画（整个井田在屏幕上时图标挤成一片）；左下角按钮可以整个隐藏；摆放模式里一直画，放大到 2.5 米/像素以内写名称 |
| 人员 | 头盔小人（蓝），下面写姓名；有仍在发生的告警（口径见 `05`"已上线告警"）的整个变红；同一基站多人合并成绿色圆点写人数，里面有人在告警时圆点描红边，点开是名单 |

**定位到某人**：先找到他所在的基站。基站已摆放：地图平滑移动并放大到合适比例（1.2 米/像素，已经更大时不缩小），弹出体征卡。未摆放：地图不动，提示"这个人所在的基站（xxx）还没有摆放位置"，并给"去摆放"入口。

阶段 4 的做法：体征卡挂在人员图标正上方，下面有指向图标的小三角；靠近地图边上时地图自动挪一挪，让整张卡露出来（上边留出搜索框的高度）。基站没摆放的人，体征卡停在地图上方正中、不带小三角，提示写在卡片里，卡片下面的按钮多一个"去摆放"：点了进入摆放模式并选中那个基站。卡片和地图一起每 30 秒刷新。

## 五、基站摆放

所有有账号的人都能用。

**流程**：

```text
1. 点地图右上角「摆放基站」进入摆放模式
2. 左边出现基站列表：搜索框、筛选（全部/未摆放/已摆放）；每行显示名称、区域、运行状态、是否已摆放；
   顶部提示"还有 N 个基站未摆放（共 M 个）"
3. 点一个未摆放的基站，鼠标变十字
4. 在地图上点击它应该在的位置，图上出现该基站图标；可拖动微调
5. 点「保存」写入数据库，点「取消」撤销这次改动
6. 保存后自动选中下一个未摆放的基站
```

列表按区域和名称排序，让相邻的基站排在一起。

阶段 4 定下的细节：

- 列表下面是"当前基站"编辑区：名称、区域、厂家名称、最后改动的人和时间，一行操作提示（"在地图上点一下它应该在的位置" / "已放到新位置，可以拖动图标微调" / "拖动图标可以移动位置"），"自己起的名字"输入框，按钮"保存""取消""删除位置"。
- 正在摆放、还没保存的基站图标外面有一圈黄色虚线，名称后面写"（未保存）"；选中的已摆放基站外面是黄色实线圈，地图移过去并放大到 2 米/像素。
- 只有第一次摆放成功后才自动选中下一个未摆放的基站（列表顺序里排在它后面的第一个，到底了从头找）；移动、改名保存后停在原基站。全部摆完时提示"全部基站都摆放好了"。
- 保存时没有改动就不提交；摆放后版本号是 1，之后每改一次加 1；未摆放的基站在接口里版本号是 0。
- 删除位置要在确认框里再点一次"删除"。
- 收到 409 时提示后端的原话（"这个基站刚刚被 xxx 修改，请刷新"），自动重新读列表，丢掉这次没保存的改动。xxx 是操作日志里最后一个改动这个基站的人。
- 退出摆放时没保存的改动直接丢掉。

摆放模式下还能：**移动**（拖动已摆放的基站，保存）、**改名**（起自己的名字，不改厂家名称）、**删除**（基站回到"未摆放"，需二次确认）。

**接口**：

| 接口 | 说明 |
| --- | --- |
| `GET /api/map/stations` | 全部基站：编码、名称、区域、运行状态、是否已摆放、坐标、版本号；`?placed=false` 只看未摆放 |
| `PUT /api/map/stations/{stationCode}/mark` | 新增或修改 |
| `DELETE /api/map/stations/{stationCode}/mark?version=` | 删除，带读到的版本号 |
| `GET /api/map/station-logs` | 操作日志（只读） |

`PUT` 请求体：

```json
{ "x": 39482000.5, "y": 3852000.5, "displayName": "新副井下口", "version": 0 }
```

新增时 `version` 传 0，修改时传读到的版本号。服务端校验：基站编码必须在 `POS_STATION` 里存在；`x`、`y` 必须在地图范围内，否则 400；`displayName` 最长 100 字符，去首尾空格。两人同时改或删同一基站，后提交的收到 409，提示"这个基站刚刚被 xxx 修改，请刷新"。两人同时第一次摆放同一基站（都传版本 0），后提交的会撞主键，同样返回 409。

**操作日志**：新增、移动、改名、删除都在**同一个数据库事务里**写一条日志（日志写失败则改动一并回滚）。记录：登录账号、时间、动作（`STATION_PLACE` / `STATION_MOVE` / `STATION_RENAME` / `STATION_DELETE`）、基站编码、改动前后的 `{ x, y, displayName }`。界面提供"查看操作记录"抽屉，倒序，可按基站筛选，服务端分页。

阶段 4 定下的细节：

- 一次保存里既挪了位置又改了名，记两条（先"移动"后"改名"），两条的前后内容一样。
- 日志里的坐标统一写 3 位小数（数据库里也存 3 位）。
- 并发的做法：先 `SELECT … FOR UPDATE` 锁住这个基站的摆放行再比对版本号，同一基站的改动排队进行；两人同时第一次摆放时，后提交的插入撞主键（`ORA-00001`），同样返回 409。
- 基站编码在 `POS_STATION` 里没有：404"没有这个基站"；名字超过 100 字：400"名称最长 100 个字"；坐标超出地图范围：400"位置超出地图范围"（范围的边上可以）。
- 抽屉每页 20 条，每条写时间、账号、动作、基站现在的名称，以及"放在 (x, y)" / "(x1, y1) → (x2, y2)（挪了 N 米）" / "名字 A → B" / "删除了 (x, y) 的位置"。选中了基站时默认"只看这个基站"，可以取消勾选看全部。

## 六、边界情况

| 情况 | 处理 |
| --- | --- |
| 厂家新增基站（`JZSS` 出现新编码） | 自动进入"未摆放"列表 |
| 厂家某基站不再出现 | 保留记录，摆放也保留 |
| 已摆放的基站状态为"通讯中断"或"故障" | 照常画，图标灰/红，体征卡提示"所在基站通讯异常，位置可能不准" |
