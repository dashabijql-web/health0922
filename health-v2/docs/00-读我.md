# health-v2 设计文档

一套专为**井下**打造的职工健康管理系统：职工佩戴智能手表上传体征，矿上的人员定位系统告诉我们谁在井下、在哪个位置，两边数据合起来在大屏上展示。页面布局和视觉风格与一套参考截图（`reference/screenshots/`）几乎一致。

| 文件 | 内容 |
| --- | --- |
| `01-总体架构.md` | 系统组成、技术选型、通用约定 |
| `02-定位文件解析器.md` | 厂家 `.txt` 定位文件怎么收、怎么解析 |
| `03-手表数据链路.md` | 手表协议、有效性判断、预警、存储 |
| `04-Oracle表设计.md` | 所有数据表 |
| `05-页面与接口.md` | 每个页面显示什么、数字怎么算、接口 |
| `06-地图与基站摆放.md` | 巷道底图、坐标系、基站摆放 |
| `07-视觉与月报.md` | 视觉规范、月度汇总翻书报告 |
| `08-开发计划.md` | 分阶段计划、验收、风险 |
| `09-页面还原规范.md` | 页面布局、位置、样式（与参考截图几乎一致），以及与截图不同的地方 |
| `10-待核对清单.md` | 设计里还没对照原始资料或真机核对过的地方，到对应阶段逐条核对 |

**一句话**：手表数据走 TCP，定位数据走文件，两条线在 Oracle 里汇合，前端只跟后端说话。两条线用**人员卡编码**（17 位）对上号。

## 一、已定的事

下表是摘要，规则原文在 `AGENTS.md` 的"已定规则"。

| 事项 | 决定 |
| --- | --- |
| 技术 | Java 21 + Spring Boot；Vue 3；Oracle（开发用本机 Docker，部署时再选版本） |
| 手表 | TCP `9001`，先用模拟器 |
| 定位数据 | 国家煤监局《煤安监办〔2019〕42号 附件2》协议；厂家经 FTP（FileZilla Server）传 `.txt`；后端每 30 秒扫描收件箱，处理完的文件备份保留；开发期直接把文件放进收件箱 |
| 直接删除的文件 | `RYCS`、`RYCY`、`RYYJCS` |
| 人员唯一 ID | 人员卡编码 |
| 卡号 | 页面显示卡编码后 5 位（国家协议规定就是矿上系统的卡号），悬停看完整 17 位 |
| 数据冲突 | 以文件头里数据上传时间最新的为准 |
| 人的位置 | 精确到"离他最近的基站"；基站坐标由用户在地图上手动摆放 |
| 基站摆放 | 所有账号可用；记操作日志（谁、何时、做了什么、前后位置） |
| 设备事件 | 低电、脱落、佩戴提醒、拆卸、红外等在大屏展示：体征信息面板标题栏显示今天的数量，点开看列表 |
| 告警口径 | 六个告警格子按"今天产生过"算人数；"已上线-告警"按"仍在发生"算（最近一次异常后 30 分钟内），恢复正常后自动变回"无告警"。告警没有状态（见 `AGENTS.md`"告警"） |
| 佩戴情况导出 | 只含绑定了手表的人 |
| 默认管理员 | 开发期账号 `admin`、密码 `admin`，登录页明文提示；上线前改密码、关提示 |
| 判定标准按岗位 | 工种归成几个岗位类别，每类一套阈值；实时告警和月报稳定性评估都用它。没归类的用默认类别 |
| 重点监护、今日关注 | 人工加入和移除，不按规则自动加；"今日关注"当天 24 点自动失效 |
| 坐标系 | EPSG:4527；GeoServer 用 WMS 1.1.1 |
