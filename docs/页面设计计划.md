# HealthNext 页面设计与 mock 验收计划

本文件管理字段、交互、视觉和前端验收。范围与进度以 [总体计划](./产品设计计划.md) 为准，业务规则与接口以 [工程计划](./工程实现计划.md) 为准。

## 1. 范围与交付方式

目标为七个业务域、**25 个主页面（含登录）**，范围见 [总体计划](./产品设计计划.md#3-七个业务域与主页面范围)。指标标签、公共详情和异常状态不另计主页面。

按总体计划 A0–A3 先确定目标产品与架构设计，再建设设计系统、契约与 mock，并验证人员—设备—事件流程；之后完成所有前端 mock，最后接后台。创新布局由 Gemini 提供可操作样板，用户确认后交 Grok 工程化；成熟列表复用经新标准验收的公共组件。生图、Figma 和工具型号不作为交付门槛。

每批交接包含字段/动作/状态契约、准确文案、集中 mock 样本、代码、截图、构建与交互结果、未完成项；创新布局补充用户确认的视觉版本。使用现有测试与截图目录，不建立重复的进度文档。演示数据不得含真实敏感资料。

导航与路由由目标页面职责和用户任务确定；本计划不绑定任何已有页面实现。

## 2. 公共设计与交互

- **主题**：深色工业风。背景 `#071018`，表面 `#0B151F` / `#101D28`，边界 `#263946`，文字 `#EAF2F5` / `#91A5AD`；青色 `#36C5D8` 表示当前操作，绿色表示正常，琥珀色表示关注，红色表示危急或破坏性操作。状态附文字/图标，不只用颜色。不堆叠发光、渐变与装饰卡片。
- **令牌与组件**：统一颜色、间距（4/8/12/16/24/32）、圆角、字号和层级；中文优先 PingFang SC，数字等宽，正文不小于 12px。应用壳、页头、筛选、按钮、输入、日期、标签、表格、分页、图表框、状态、抽屉与弹窗集中复用；人员和体征组件留在业务层。菜单按七域组织，具体宽度由响应式布局决定。
- **深色状态**：默认、悬停、焦点、选中、禁用、加载、错误都统一。挂到 body 的下拉、日期面板、Tooltip、消息和对话框也须深色；不能只修页面内按钮。
- **响应式**：检查 1920×1080、1440×900、1280×800、1024×768、390×844。窄屏可将次要列收到详情；主要信息、筛选和操作仍可达。地图与人体提供移动摘要和降级。抽屉内容可滚动，关闭及底部动作可点，键盘焦点可见并可返回触发位置。
- **数据状态**：区分加载、空业务、筛选无结果、部分缺失、陈旧、失败、缓存、无权限、只读和提交中。刷新失败可保留同一对象缓存并注明数据时间；切换对象、权限撤销或记录不存在时不得展示错误对象或无权缓存。未知不是 0，采集时间不是刷新时间。
- **上下文**：人员/设备/事件复用公共详情，同一时刻只开一个主要侧栏，切换内容可返回。下钻携带对象、日期和筛选，条件可见；返回保留页码和滚动，链接刷新可恢复选择。未实现入口明确提示，不能跳到无关页面。
- **操作**：成功后重新读取当前数据层并更新详情、名单与摘要。保存失败保留输入，冲突后重新读取供用户核对，防止重复提交。危险操作说明对象及影响。mock、未配置、命令发送、设备确认、结果返回分别表达，不冒充真实执行。
- **统计与图表**：显示单位、区间、覆盖/样本数、采集时间与聚合方式。全量筛选、摘要和分页在数据层统一计算；人数按人去重，事件数单独统计。无样本不画假曲线，合成趋势注明演示，缺失区间不连成正常直线。

## 3. 主页面职责与交互目标

以下按用户任务定义 25 个主页面。全部处于新方案待设计、待实现、待验收状态。具体布局、导航路径和组件结构由设计阶段确定，不预设左右分栏、表格形态或既有路由。

### N01 登录

提供清晰的身份认证、服务状态和会话恢复入口。覆盖输入校验、提交、认证失败、服务不可用和会话过期；成功后进入有权限的目标页面。品牌与登录视觉由统一设计系统定义。

### N02 工作台

回答当前用户今天优先处理什么，组织个人任务、紧急事项、现场摘要和常用入口。每个可操作摘要明确对象、范围和时效，下钻应用相同条件；处置后任务与统计同步。未配置的班次、准入或外部能力明确说明。

### N03 现场态势

围绕“谁在哪里、当前状况如何、需要做什么”组织地图、实时人员、值班安排和事件的协同视图。选择人员、区域或事件后在视图间保持上下文；值班安排与在线状态分别表达。

实时指标独立显示数值、采集时间、有效性和新鲜度；在线窗口与新鲜度可配置，未来时间、陈旧和缺失分别处理。地图支持图层、搜索、区域查看、轨迹与测距，展示坐标来源、版本和位置时间；缺少可靠位置时不生成假坐标。

### N04 人员档案

管理人员身份、组织、岗位、在职状态及设备关系，支持搜索、筛选、登记、编辑与导入校验。导入先预览错误与冲突，再提交；失败不留下部分人员或错误绑定。可进入人员健康、设备和授权范围内的相关事件。

### N05 人员健康详情

围绕一个人的身份、当前读数、历史变化、活动情况及待处理事项组织信息。指标分别显示单位、时间与质量，支持指标切换和日期查询；趋势说明样本数、来源与聚合方式，缺失区间不画成正常连续值。

切换人员同步链接并隔离缓存，纯历史查询不随当前读数刷新重建；提供事件、设备和人体入口。没有真实关联事件时显示无关联，联系与控制能力按配置和权限开放。

### N06 沉浸人体

用可旋转、缩放的人体呈现当前人员的指标分布，选择热点可查看读数、依据和相关事件。提供重置视角、减少动画及返回入口；模型加载失败或图形性能不足时仍能查看数据。模型表现不能暗示未经证实的器官病变或心电测量。

### N07 入井健康准入

围绕日期、班次和人员完成检查、复检及人工决定。展示有效读数、采集时间、规则版本和命中依据；数据不足或过旧不能作为合格证据。人工覆盖建议需理由，决定与复检过程可追溯，支持连续处理下一人。

### N08 事件中心

统一发现和处理健康超限、设备报警及趋势风险，支持来源、代码、严重度、人员、区域、负责人、状态与时间筛选。我的待办、未分派、超时等视图使用同一事件模型和统计口径。

事件详情提供证据、恢复状态、负责人、时限与动作时间线；确认、分派、处理、关闭及误报遵循工程契约。严重度与来源独立，SOS 仅表示设备求救；冲突提示可核对，重复提交不产生重复动作。

### N09 处置与追溯

查询事件经过、处置结果及对应原始异常证据，区分检测记录和人工操作记录。按对象、人员、时间、来源和结果检索，可查看备注、附件、版本与外部动作结果；历史终结记录只读，导出遵循权限与查询范围。

### N10 设备台账

管理设备身份、型号、固件、启停、在线、电量与绑定历史，支持登记、导入、绑定、解绑和停用。设备标识稳定，绑定冲突有明确原因；批量操作逐项返回结果。未知电量与 0% 分开，可进入控制、通信和关联人员。

### N11 设备控制

在指定设备与任务上下文中发起允许的指令，展示参数、影响和执行过程。请求接收、指令发送、设备确认、业务结果、超时及失败分别表达；离线、权限不足或任务冲突时说明限制。mock 指令全程标注模拟执行。

### N12 通信报文

为运维提供按设备、协议类型、方向、解析结果和时间的检索，支持暂停跟随、分页及详情复制。原始文本脱敏，解析字段、接收时间、设备时间、错误原因可追查；大量数据和连接中断不破坏当前选择。

### N13 分析总览

呈现健康覆盖、风险变化、重复异常及处置效率，支持时间和组织范围查询。人数、事件数、记录数及覆盖率分别定义分母和范围；图表下钻可验证统计依据，部分样本与无数据状态清楚可见。

### N14 多维健康分析

按心率、血压、血氧、体温、压力、睡眠和趋势风险选择分析任务，交叉查询部门、班组、班次、岗位与区域。提供趋势、分布、分组比较和对应明细，当前异常与历史记录使用清晰区分的查询范围。

心率区分偏低/偏高；血压保留收缩压与舒张压；血氧区分有效、偏低、未佩戴和无效；压力注明设备指标含义；睡眠说明日期与上传覆盖；趋势风险展示样本和规则证据。指标可比较性不足时说明限制，不合成为虚构医学评分。

### N15 报告中心

按对象、类型和时间生成报告，支持任务排队、生成、取消、重试、预览与授权下载。报告注明数据范围、样本、截止时间、生成方式和引用来源；AI 辅助内容明确标记。

### N16 AI 助手

围绕授权数据查询、解释和报告草稿组织会话与任务。回答附可追查的数据范围、日期、样本及引用，可下钻人员和事件；支持中止、失败重试和无依据提示。拒绝越权查询，不把辅助解释当医学诊断。

### N17 用户管理

管理账号、角色、组织范围、启停和会话相关操作，支持查询、登记、编辑与密码重置。敏感动作说明对象及影响，权限变更可追溯；只读用户与无权用户有明确行为。

### N18 角色与权限

配置角色可访问的功能、动作和数据范围，保存前展示授权变化及影响。支持权限检索、关联用户查看与未保存提示；有引用的角色不能无提示删除，功能权限与数据范围分别验证。

### N19 组织架构

管理部门和班组的层级、负责人、成员及状态，支持搜索、调整关系与停用影响预览。组织结构禁止循环，关联人数可下钻，调整后各页面的数据范围保持一致。

### N20 岗位与工种

管理岗位、工种、风险分类、人员关联和适用规则。支持查询、编辑、关系调整及停用；变更前说明对规则和准入的影响，人员与规则入口携带选中条件。

### N21 区域配置

管理区域类型、层级、地图关联、负责人及启停，查看关联人员、设备和事件范围。空间边界与地图版本可核查，缺地图或位置来源时不伪造空间信息；变更显示影响并保留记录。

### N22 班次配置

管理时段、跨日规则、组织适用范围及启停，提供冲突校验与日期解释。值班安排、健康准入和分析使用一致的班次归属，调整后可预览影响。

### N23 风险与事件规则

按健康阈值、设备报警和趋势规则管理草稿、校验、发布及版本。配置适用范围、条件、持续/恢复时间、严重度、时限及通知关联，发布前展示差异与影响；草稿不生效。设备报警不套用数值体征阈值，未配置能力不可假启用。

### N24 通知与集成配置

管理渠道、连接、适用事件、升级策略和投递记录。测试连接与保存分开，密钥只显示已设置；清楚区分未配置、测试、可用和失败，未连接外部系统时不声称已发送。

### N25 系统设置与审计

通过内部视图管理系统参数、安全策略、资源及操作审计。配置变更可校验、比较和追溯；日志按执行人、动作、对象、时间、结果和请求编号检索，敏感字段脱敏，授权导出。

## 4. 公共交互能力

通用底座提供应用壳、导航、主题、表单、查询、反馈、焦点管理和会话处理，禁止依赖健康领域对象。人员、设备、事件和区域详情由业务模块提供，跨页遵守相同对象与动作契约；呈现为抽屉、面板或独立视图由任务复杂度决定。

页面从对象跳到关联对象后保留返回路径，恢复筛选、页码和选择。异常、确认和任务进度统一交互语义；组件复用以新设计系统和契约为准。

## 5. 关键任务流程

- 值班：工作台识别优先事项 → 事件中心核对证据 → 查看人员/现场上下文 → 分派与处理 → 满足条件后关闭 → 追溯结果。
- 人员：档案检索 → 健康详情查询历史 → 人体指标查看 → 关联事件 → 返回同一人员及查询区间。
- 现场：区域筛选 → 地图与实时名单联动 → 查看人员状态 → 进入相关事件或授权联系。
- 准入：选择班次与检查队列 → 核对读数和规则 → 复检 → 人工决定 → 处理下一人。
- 运维：发现设备问题 → 台账确认身份与绑定 → 通信定位原因 → 发起允许的模拟控制 → 查看任务结果。
- 管理：组织/角色配置 → 查看权限与影响 → 保存 → 在不同角色会话验证访问范围和拒绝路径。

## 6. 设计交付

每个页面交付任务说明、信息层级、关键流程、字段及动作契约、正常与异常状态、响应式行为和可操作 mock。创新布局由 Gemini 先完成设计样板，用户确认后工程实现；实现进度以新标准逐页验收记录为准。设计稿不能代替业务行为测试。

## 7. 每批验收与证据

- 覆盖默认、空业务、筛选无结果、首次失败、缓存失败、部分/陈旧数据、只读和无权限；验证超过一页的样本、切换筛选回首页、返回恢复条件。
- 事件确认/分派后摘要与名单同步；处理完成、受限关闭、允许关闭、误报分别测试。终结后只读，失败保留输入；双击不重复执行，并发修改有冲突提示。详细规则以工程计划第 9 节为准。
- 人员改名、设备改 IMEI、绑定/解绑、冲突及停用在跨页往返后保持一致；失败不能留下半成品，普通资料保存不能重算设备 ID。0% 与未知电量分别验证。
- 五档视口逐项检查展开下拉、日期面板、表单和公共抽屉；不只检查 scrollWidth，也检查文字裁切、重叠、滚动和按钮可达。与用户确认的创新布局核对信息层级，明显调整提供具体对比。
- 记录范围编号、视觉版本（适用时）、代码版本/差异、数据模式、测试时间、步骤结果、五档截图和未验收项。执行方报告与独立复核分开，不把未运行写成通过。

全部通过后记录对应页面的 mock 验收结果；真实 API、Oracle 持久化、服务端授权和设备链路在后台阶段另验。当前进度统一维护在总体计划。
