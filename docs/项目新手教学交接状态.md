# 项目新手教学计划与 AI 接手状态

> 这是本项目的新手教学状态文件，也是不同 AI agent 之间的交接文件。
> 新 agent 不应依赖聊天记录来判断学习进度；开始教学前必须先阅读本文件、根目录 `AGENTS.md` 和 `README.md`。

## 1. 文件目的

这份文件解决两个问题：

1. 给刚学会写代码的学习者一条循序渐进的项目阅读路线。
2. 给后续接手的 AI agent 一份稳定的上下文，避免因为聊天上下文被压缩、切换线程或更换 agent 而忘记学习进度。

本文件不是代码设计文档，也不是问题列表。它只记录项目教学所需要的事实、阶段、证据和下一步行动。

文件命名约定：除根目录的 `README.md` 和 `AGENTS.md` 外，项目中的 Markdown 文件使用中文文件名。已有英文文件名按本约定逐步改名，改名时必须同步更新引用；文件内容和 Git 历史不因改名而改变。

表达约定：所有 Markdown 尽量用普通中文和短句。第一次出现的技术词要说明它是做什么的；代码中的类名、接口路径、命令和协议号可以保留原样，但后面要用日常语言解释，不能只列术语。

## 2. 新 agent 启动协议

任何新的教学 agent 开始工作时，必须按以下顺序执行：

1. 阅读根目录 `AGENTS.md`，尤其是数据库边界、认证、手表数据流和 Git 规则。
2. 阅读根目录 `README.md` 的“新手接手学习手册”章节。
3. 阅读本文件的“当前进度”“下一课”和“最近教学记录”。
4. 在根目录执行只读检查：

   ```bash
   git status --short
   git branch --show-current
   git log -5 --oneline
   ```

5. 向学习者报告：当前阶段、已经有证据证明的能力、下一节课的目标。
6. 一次只讲一个小主题，讲完后给一个小练习或检查问题。
7. 只有学习者明确要求修改代码时，才修改代码；教学过程默认只读。
8. 本轮结束前，把学习结果和下一步写回本文件。

不要做以下事情：

- 不要假设聊天历史仍然完整。
- 不要把“读过文件”直接当成“已经理解”。
- 不要一次讲完整个项目或粘贴大量源码。
- 不要为了清理工作区执行 `git reset --hard`、`git checkout -- .` 或删除已有改动。
- 不要把新库 `health_new` 的空数据语义套用到当前老库 `health` 项目。

## 3. 学习者画像和教学方式

学习者是刚学会写代码的新手，目标是逐步接手并看懂这个项目，而不是马上重构项目。

教学要求：

- 使用通俗中文，第一次出现技术词时先解释它解决什么问题。
- 多用“流水线”“信封”“快递站”等类比，但类比后必须落回代码文件和实际行为。
- 先建立地图，再读局部；先读一条完整链路，再横向比较同类模块。
- 每轮最多引入一个主要概念和一小组文件。
- 先让学习者回答，再补充答案；回答错误时指出错在哪里并重新解释。
- 不为了显得完整而讲暂时不影响主链路的细节。
- 以代码、配置和实际运行结果为事实来源，不以猜测替代证据。

每轮教学建议使用以下结构：

```text
本轮目标：
要看的文件：
通俗解释：
代码中的关键位置：
小练习：
通过标准：
下一步：
```

## 4. 项目固定事实

以下事实来自当前项目约定，除非代码、配置或实际运行结果已经改变，否则教学 agent 不得自行改写：

| 项目部分 | 当前事实 |
| --- | --- |
| 前端 | `HealthShow`，Vue 3、Vite、Vue Router、Vuex、Element Plus、ECharts |
| 后端 | `HealthData`，Java 21、Spring Boot、MyBatis-Plus、Sa-Token、Netty |
| 数据库 | 当前 `health-old` 固定连接老库 `health` |
| Redis | 手表健康数据缓冲、实时快照、在线状态和失败重试 |
| HTTP | 后端默认 `8080`，context path 为 `/health` |
| 前端 | Vite 默认 `9528`，开发请求前缀为 `/dev-api` |
| 手表 TCP | Netty 默认监听 `9000` |
| SQL Server | 默认 `127.0.0.1:1433` |
| 本地账号 | 默认 `admin / admin123`，生产环境不能沿用 |
| 数据表 | 健康记录和预警记录按月分表 |
| Git 边界 | 根目录是唯一 Git 仓库，两个子目录不是独立仓库 |

主要数据流：

```text
浏览器 Vue 页面
    -> Vite 代理 /dev-api
    -> Spring Boot Controller
    -> Service 业务逻辑
    -> Mapper / SQL
    -> SQL Server

手表 TCP 字节流
    -> WatchProtocolDecoder
    -> WatchMessage
    -> WatchDataHandler
    -> 设备和人员绑定解析
    -> Redis 缓冲 / 实时快照
    -> 月表落库和预警判断
```

## 11. 状态更新规则

- 更换 agent、切换线程或上下文压缩前更新。

### 怎么更新

1. 更新“当前进度”的 YAML 摘要。
2. 更新阶段状态，但只根据通过标准更新。
3. 在“尚未有学习证据的事项”中勾选或取消勾选。
4. 在“最近教学记录”追加记录，不删除历史。
5. 把下一轮唯一目标写入“下一课的固定计划”。

### 什么时候不能更新为已完成

- 只是把文件打开看过。
- Agent 自己讲完了，但学习者没有复述或练习。
- 服务没有启动，只是根据配置猜测运行结果。
- 代码、配置和文档互相矛盾，事实还没有核对。

## 12. 最终完成标准

当学习者满足以下条件，才认为已经具备“接手项目”的基础：

- 能独立启动或检查前后端基础服务。
- 能从页面请求追到 Controller、Service、Mapper 和数据库。
- 能解释登录、权限、月表、Redis 和异步写入。
- 能追踪一条手表数据从 TCP 到落库和预警。
- 能区分实时状态、健康记录和预警事件。
- 能用日志、Network、Redis 和 SQL 逐层排障。
- 能完成一个小改动并运行对应验证。

达到这些标准后，才进入具体需求开发、重构或生产问题排查。
